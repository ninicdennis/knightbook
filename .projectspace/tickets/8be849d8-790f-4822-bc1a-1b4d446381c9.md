# Guide link check treats link syntax inside code as a real link

## Intended outcome
A guide can show Markdown link syntax as an example, in inline code or a code block, without the build refusing it as a broken link.

## Acceptance criteria
- `brokenGuideLinks` in `apps/website/src/docs/guides.ts` ignores link syntax inside inline code spans and fenced code blocks.
- A fixture guide whose body contains `` `[the spec](spec.md)` `` and a fenced block with a relative link builds, and a real broken link in the same guide is still reported.
- Real links between guides are still checked exactly as before.

## Notes
Found while writing the projects and documents guide (b794d542): the example `` `[the spec](spec.md)` `` stopped the build with "These guide links lead to no published guide", because the check runs a regex over the raw Markdown body. The guide was reworded to avoid link syntax, so nothing is blocked on this.

## Handoff
**What changed:** `brokenGuideLinks` in `apps/website/src/docs/guides.ts` now runs its link regex over the guide body with code removed, by a new `withoutCode`. It drops fenced code blocks (backtick or tilde fences, closed by a fence of the same character at least as long, or running to the end when unclosed) and inline code spans (a backtick run closed by a run of the same length, within one paragraph). A backtick with no partner stays plain text, so a link after it is still checked. Indented (four-space) code blocks are not treated as code, because list continuation lines look the same and hold real links. The fixture guide in `docs.test.ts` gains a single-backtick span, a double-backtick span and a fenced block, each holding a link that leads nowhere.

**How it was checked:**
- `apps/website/src/docs/docs.test.ts`: 18 of 18 pass. With the `guides.ts` change stashed, the fixture build failed naming `spec.md`, `ticket.md` and `../not-a-guide/` as broken links.
- The broken-link test also puts an unpaired backtick before a real link (`../also-missing/`) on the same line as code spans, and expects that link reported and none of the code examples. With the span regex allowed to cross paragraphs (the first draft), this test failed on `spec.md`.
- `pnpm check` passed (Node 22 in a cloud container; the repo asks for 24).
- Verifier, first draft: 1 covered, 2 weakly covered. It found that an unpaired backtick could swallow later real links across paragraphs, and that the real link beside the code spans was never asserted. Both were fixed as above. It also compared the links extracted from the six real guides with and without `withoutCode`: identical counts.

**Not verified:** the website browser tests (`site-accessibility.test.ts`, 37 tests) and packaged-app tests skipped, as no browser install or package was present; neither touches the link check. `withoutCode` has no unit test of its own (guides.ts imports `astro:content`), so tilde fences, longer fences and unclosed fences are covered only by reading, not a test.

**For you to check:** a guide containing `` `[the spec](spec.md)` `` builds, and a real broken link still stops the build.
