# Split the renderer contract, which is close to the size limit

## Intended outcome
`apps/desktop/src/shared/contract.ts` is back well under the project's 400-line hard limit, so the next contract operation can be added there without splitting in a hurry.

## Acceptance criteria
- `contract.ts` is under 300 lines, with the moved types in their own `*-contract.ts` files beside it, as `ticket-create-contract.ts`, `ticket-edit-contract.ts` and `document-search-contract.ts` already are.
- `KnightbookApi` still names every operation, and the renderer, preload and host change only their imports.
- `pnpm check` passes with no behaviour change.

## Notes
Found on 2026-09-25 while adding document search (bd3357e9): the file reached 393 lines after that ticket and the blocker ticket (468fa456) each added one API interface. Ticket search types (`SearchScope`, `SearchHighlight`, `TicketSearchView`) and the project view types are the obvious first candidates. `apps/desktop/src/renderer/App.tsx` is at 376 lines and may need the same soon.

## Handoff
**What changed:** On branch `feature/file-organization`, uncommitted. `contract.ts` went from 393 to 249 lines. The moved types and operations went into four new files, each defining an API interface the same way `TicketEditApi` does:
- `ticket-search-contract.ts`: `SearchScope`, `SearchHighlight`, the ticket search views and `TicketSearchApi` (`searchTickets`).
- `archive-contract.ts`: `ArchiveTarget`, `ArchiveFailureView`, `ArchiveOutcome` and `ArchiveApi` (`archiveTickets`, `restoreTicket`).
- `project-setup-contract.ts`: `ChosenFolder`, `RememberedProject`, `FolderInspection`, `SetupOutcome` and `ProjectSetupApi` (remembered projects, choose, inspect, set up).
- `settings-contract.ts`: `ColorSchemeChoice`, `AppSettings`, `WindowTitleProject` and `SettingsApi` (read and save settings, window title).

The three MCP operations moved into the existing `mcp-contract.ts` as `McpApi`. `KnightbookApi` now extends these five, so it still names every operation. The moved types are not re-exported from `contract.ts`; 26 consumers in main, the renderer, `shared` and the board preview had only their `import type` lines changed. Project view types stayed in `contract.ts`, because nearly every consumer uses them.
**How it was checked:** `pnpm check` exits 0, with the same test-file counts (desktop 53, core 23, mcp 8, packaging 7, editor-preservation 2). The change is type-only, so the built JavaScript does not change.
**Not verified:** The packaged app was not rebuilt, as before; there is nothing at runtime to see.
**For you to check:** Look over the grouping of the four new contract files. `App.tsx` is now at 380 lines and is not part of this ticket.
