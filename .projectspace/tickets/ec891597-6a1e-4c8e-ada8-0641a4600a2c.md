## Intended outcome
The Linux deb starts on a fresh Ubuntu 22.04 as well as 24.04, with nothing installed by hand.

## Acceptance criteria
- The deb's `Depends` includes `libgbm1`, which Electron links against.
- The test that checks the deb's dependencies fails without it.
- Installed with `apt install ./…deb` in fresh `ubuntu:22.04` and `ubuntu:24.04` containers, `ldd` finds no missing library and the window opens.

## Notes
Found on 2026-10-22 after the ALSA fix (75d7db08): on a fresh Ubuntu 22.04 the app still exits with `error while loading shared libraries: libgbm.so.1`. electron-builder's default deb dependencies leave out `libgbm1`; on Ubuntu 24.04 it happens to arrive through other dependencies. Reported by another project thread and reproduced with a 0.2.2 deb built from main.

## Handoff
**What changed:** `libgbm1` added to `deb.depends` in `apps/desktop/electron-builder.yml`, with a third case in `apps/desktop/scripts/deb-depends.test.mjs`. The installation guide's 0.2.0 workaround now names both libraries, and the packaging findings record the 22.04 result.

**How it was checked:**
- Reproduced first: the 0.2.2 deb (with the ALSA fix) in a fresh `ubuntu:22.04` container installed `libasound2` 1.2.6.1 but `ldd` reported `libgbm.so.1 => not found`.
- The new test fails without the config change and passes with it.
- A 0.2.3 deb built from this has `Depends: …, libasound2t64 | libasound2, libgbm1`. In fresh Ubuntu 22.04.5 and 24.04.5 containers, `apt install ./…deb` left no missing library under `ldd`, and the Knightbook window came up on Xvfb with no loader error.
- `pnpm check` passed (under `xvfb-run`).

**Not verified:** Debian 12 and 13, and a real desktop machine.

**For you to check:** the dependency list and the guide's workaround wording.
