## Intended outcome
The Linux deb installs everything Knightbook needs to start, including on a minimal Ubuntu or Debian system.

## Acceptance criteria
- The deb's `Depends` includes the ALSA library, as `libasound2t64 | libasound2`, so `apt` installs it on Ubuntu 24.04 and Debian 13 as well as Ubuntu 22.04 and Debian 12.
- The other default dependencies electron-builder writes are kept (setting `deb.depends` replaces them), checked against the built package's control file.
- Installed with `apt install ./…deb` in a fresh `ubuntu:24.04` container, the app starts without installing anything else by hand.
- The installation guide's note telling readers to install `libasound2t64` themselves is removed or limited to versions before the fix.

## Notes
Found in the Linux validation (b2a51f35) on 2026-10-22 with the published 0.2.0 deb: in a fresh Ubuntu 24.04 container `knightbook` exits with `error while loading shared libraries: libasound.so.2`. `apt install libasound2t64` fixes it. A desktop install of Ubuntu already has the library, so this mainly affects minimal and server installs. Recorded in docs/experiments/packaging-findings.md. The installation guide carries a workaround until this ships.

## Handoff
**What changed:** `apps/desktop/electron-builder.yml` sets `deb.depends`: electron-builder 26.15.3's nine default deb dependencies plus `libasound2t64 | libasound2`. New `apps/desktop/scripts/deb-depends.test.mjs` loads the config through electron-builder's own loader and checks the ALSA entry is there and every default from `FpmTarget.getDefaultDepends('deb')` is kept. The installation guide's workaround note now says it applies to the 0.2.0 package only, and the packaging findings record the fix.

**How it was checked:**
- The new test fails without the config change (the ALSA test fails, the defaults test passes) and passes with it.
- A deb built with `pnpm pack:installers --linux deb -c.extraMetadata.version=0.2.2` has `Depends: libgtk-3-0, libnotify4, libnss3, libxss1, libxtst6, xdg-utils, libatspi2.0-0, libuuid1, libsecret-1-0, libasound2t64 | libasound2` (`dpkg-deb -f`).
- In a fresh `ubuntu:24.04` container, `apt install ./Knightbook-0.2.2-linux-amd64.deb` installed `libasound2t64` itself, `ldd` found no missing library, and the window opened to **Choose a project folder** with nothing installed by hand.
- `pnpm check` passed (under `xvfb-run`, since a local package existed and the packaged-window tests ran).

**Not verified:**
- Ubuntu 22.04 and Debian 12, where the `libasound2` alternative is the one apt should pick. Only Ubuntu 24.04 was installed.
- A real desktop machine; this was a container.
- The `verifier` agent was not run; the two criteria with tests were checked by making the test fail without the change.

**For you to check:** the dependency list in `electron-builder.yml`, and the reworded note in the installation guide. The fix reaches users in the next release you start by hand.
