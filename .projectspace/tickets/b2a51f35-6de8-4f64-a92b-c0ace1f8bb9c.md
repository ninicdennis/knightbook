# Validate on Linux (deb, x64)

## Intended outcome
The core workflow is confirmed on a real Linux x64 machine using the deb package, the Linux format D-028 ships first.

## Acceptance criteria
- The deb installs on a maintained distribution (say which one and its version) and the app starts.
- An MCP client connects with the app closed and no system Node on the PATH, and can list and update tickets.
- The saved MCP command still works after reinstalling or upgrading the deb, since the fixed install path is why deb ships first.
- Edits made outside the app (editor, Git) appear correctly after focus or Refresh.
- A project created on Windows opens on Linux without broken links, and the reverse.
- Results recorded in the packaging findings: distribution, desktop environment, package tested, what passed, what did not.

## Notes
Split from "Validate macOS and Linux" (5ddb9586) on 2026-09-26 so each platform can be validated on its own hardware. AppImage is out of scope here: it is validated on Linux as part of ticket 68f54f52, which makes the MCP helper persistent, and stays out of released targets until then (D-028). Linux arm64 and rpm are not built (D-028). The app window has only been launched on Windows so far; CI builds and tests Linux but does not open the window. The user validates on their own hardware.
