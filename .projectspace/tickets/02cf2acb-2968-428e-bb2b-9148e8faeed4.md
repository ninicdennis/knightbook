# Make the renderer test fixture's mutations return a result

## Intended outcome
A test that carries a board mutation through `makeApi()` gets a usable result instead of an unhandled rejection.

## Acceptance criteria
- The mutating members of `makeApi()` in `apps/desktop/src/renderer/test-fixtures.tsx` resolve to a valid `Result<ProjectView>` by default, rather than `undefined`.
- A test that triggers a move or a completion produces no unhandled rejection.
- Existing suites still pass unchanged; any test that wants a failure result still overrides it locally.

## Notes
Found while writing `Keyboard.test.tsx`. `setTicketStatus`, `completeTicket` and the other mutations are bare `vi.fn()`, so they resolve to `undefined`, and `App.tsx`'s `apply()` then reads `result.ok` off it. Vitest reports this as `TypeError: Cannot read properties of undefined (reading 'ok')` in an "Unhandled Errors" block while every test still shows as passing, which is exactly the shape of failure that gets ignored.

No current suite trips it, because the others assert the mutation was called rather than letting the app consume what it returns. `Keyboard.test.tsx` works around it locally. This is a sharp edge in the shared fixture, not an app bug.

## Handoff
**What changed:** (uncommitted, branch `feature/easy-wins`) In `apps/desktop/src/renderer/test-fixtures.tsx`, the eight mutations that return `Result<ProjectView>` (`setTicketStatus`, `setTicketType`, `completeTicket`, `recordVerificationIssue`, `resolveVerificationIssue`, `recordTicketReview`, `restoreTicket`, `reorderBacklog`) now resolve by default to `{ ok: true, value: project() }`: succeeded, board unchanged. Tests that need a different board or a failure still override locally, as `Keyboard.test.tsx` does. `archiveTickets` returns an `ArchiveOutcome` rather than a board, so it was left as it was.

**How it was checked:** new `apps/desktop/src/renderer/TestFixtures.test.tsx` calls every one of those defaults, then carries a card move through the app with no local overrides and fails on any unhandled rejection. Run against the old fixture, both tests failed with the exact error the note describes (`Cannot read properties of undefined (reading 'ok')`); against the new one they pass. The full desktop suite is 264 passed plus the existing network skip, with no Unhandled Errors block. Desktop typecheck is clean. No existing test was changed.

**Not verified:** completion was not carried through the dialog in the new test, only called directly. It uses the same result path as the move.

**For you to check:** `pnpm --filter @knightbook/desktop test` shows no "Unhandled Errors" section.
