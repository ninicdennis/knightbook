# Write the troubleshooting and support guide

## Intended outcome
`/docs/troubleshooting/` helps users recover from common problems without risking their project data, and shows them how to ask for help safely.

## Acceptance criteria
- Covers each symptom in the spec §7 table: installer will not run, MCP runtime missing, MCP not connected, wrong project appears, documents or changes missing, write conflict or malformed record, unexpected Done or review state, behaviour changed after an update.
- Each entry gives the first checks, the expected result, the next safe action, and when to contact support.
- Links to the chosen support destination and says what to include (app version, OS and architecture, reproduction steps, redacted errors) and what never to post (whole private projects, credentials, unredacted client logs).
- Other guides link to the matching entry here at each likely failure point.

## Notes
Spec §7 "Troubleshooting and support". Error text quoted in the guide must match what the release actually shows.
