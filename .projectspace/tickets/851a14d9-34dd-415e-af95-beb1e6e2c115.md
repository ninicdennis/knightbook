# Include and remove documents from the app

## Intended outcome
Organize a project's documents without an AI tool.

## Acceptance criteria
- Include and remove documents and folders in place. Removal never deletes the source file.
- Uses the same core operations as MCP.
- Included documents that no longer resolve are shown, with a way to drop the entry.

## Notes
Setting up the project itself moved to the one-click setup ticket, so this one is narrower than it was first written.

## Handoff

**What changed:** The Documents view now has an "Included from" section listing the manifest entries, with an Include menu above it and a remove control on each entry.

- `apps/desktop/src/main/documents-ipc.ts` adds three handlers: `documents:includeFiles`, `documents:includeFolder` and `documents:removeEntry`. They call `includeDocuments` and `removeFromWorkspace` from `@projectspace/core` -- the same functions the MCP server's `documents_include` calls -- so a document included here is indistinguishable from one an AI included.
- Files and folders are two separate actions deliberately: Electron cannot show a single dialog that selects both on Windows and Linux. The picker opens at the project root, and anything resolving outside it is refused by the core operation rather than stored.
- `apps/desktop/src/renderer/components/IncludedEntries.tsx` (new) renders the entries. It deliberately lists *entries*, not documents: a document included through a folder has no manifest entry of its own, so offering to remove it individually would offer something the manifest cannot express. Each entry says what it currently contributes ("2 documents"), or why it no longer resolves.
- Removal asks first, and the confirmation states plainly that the files stay where they are on disk -- "remove" is the word people read as "delete".
- Entries that no longer resolve are listed in the same place as the rest, in orange, each with the same remove control, so a stale entry can be dropped. The previous "Included but missing" alert is gone because this replaces it.
- The empty state now offers the include actions instead of only pointing at MCP.

**How it was checked:** `pnpm check` passes: lint, formatting, typecheck and 307 tests, 0 failures. 8 new tests in `apps/desktop/src/renderer/Documents.test.tsx` cover the entry list and counts, an unresolved entry being shown with a way to drop it, the absence of a per-document removal for a folder-included document, the confirmation wording, that removal sends the manifest entry rather than a document path, and that a refused removal keeps the entry and explains itself. Core already tests that removal leaves the source file intact (`packages/core/src/documents.test.ts`).

The view was also exercised in the design preview (`pnpm preview:board`), including the confirmation dialog.

**Not verified:** The native file and folder pickers were not opened -- the preview stubs the host, and the tests mock it, so `dialog.showOpenDialog` itself is untested here. That means the multi-select file filter, the folder picker, and the "picked something outside the project" path have not been run in a real Electron window. `apps/desktop/src/renderer/components/DocumentsView.tsx` is now 302 lines, just past the 300-line guideline; it was not split because the addition is one section, but it is the next file that would want splitting.

**For you to check:** Run the packaged or dev app and include a real file and a real folder, then remove each. Confirm the file is still on disk afterwards. Try picking a file from outside the project folder and see whether the refusal message is clear enough. Judge whether listing manifest entries, rather than a remove action on each document, is how you would expect it to work.
