# Show the app version inside the app

## Intended outcome
A person reporting a problem can read which Knightbook version they are running from the app itself.

## Acceptance criteria
- The running version (from the package, as `app.getVersion()` reports it) is shown in one findable place, such as the settings menu or an About entry.
- The bug-report template and the troubleshooting guide say where to find it.

## Notes
Created 2026-10-21 while writing the GitHub bug-report template (c125336d): the app shows its version nowhere, so the template can only point at the installer file name. Changes the desktop app, so its merge releases a new version (D-041).

## Handoff (2026-10-21)

**What changed**
- New contract operation `appVersion()` (`app:version`), answered in the host by `app.getVersion()` (`main/project/settings-ipc.ts`).
- Settings gains an **About** section showing "Knightbook <version>". 0.0.0 is what every unstamped build reads (CI stamps only release installers), so it is labelled "a development build, not a release". A failed read says "The version could not be read." rather than leaving a blank.
- The bug-report template, the troubleshooting guide's "What to include" list and the installation guide's update steps say where to find it, and fall back to the installer file name when no project opens. Rebased onto main after #3, #4 and #5; the troubleshooting guide is now written for 0.2.0 and its test asserts that and the Settings/About pointer.

**How it was checked**
- `apps/desktop`: 665 tests pass, including the three new Settings tests (version 0.10.3 shown exactly, 0.0.0 labelled unreleased, a rejected read says so) and `settings-ipc.test.ts` (the handler returns the mocked `app.getVersion()` value 0.10.3).
- `pnpm check`: lint, format and typecheck pass. In the full parallel run one website build test (`discovery.test.ts`, duplicate titles) hit its 5 s timeout; it passes alone, and the website suite passes on its own (132 passed).
- Layout pass in `pnpm preview:board` at 800px dark and 1600px light: the About section sits under the storage note, nothing clipped.
- Verifier: 1 covered, 0 weakly covered, 0 uncovered, 1 not a code criterion (met). Its caveat that Settings needs an open project was addressed in both texts.

**Not verified**
- The version in a real packaged window; no package was built here, so the packaged-app tests were skipped. A stamped release is the first build that will show a real number.
- The preload channel name is matched by reading only; no test covers the preload (none exist in the repo).
- Settings, and so the version, is reachable only once a project is open.

**For you to check**
- After the release this merge produces, open Settings in the installed app and confirm it shows that release's version.
