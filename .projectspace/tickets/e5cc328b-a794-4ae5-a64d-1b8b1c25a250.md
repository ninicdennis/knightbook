# Clear reading hierarchy

## Intended outcome
Ticket descriptions and project documents are comfortable to scan and read, with a stronger title hierarchy and quieter supporting information.

## Acceptance criteria
- Keep the existing system font and establish a consistent scale for dialog titles, authored headings, prose, links, lists, and metadata using the design-direction document as the starting point.
- Ticket titles remain visually stronger than body headings. Preserve every authored heading and paragraph even when the body repeats its title; do not rewrite Markdown to achieve the visual result.
- Retain roughly 65–78ch prose measure and comfortable line/paragraph/list spacing. Check a long acceptance-criteria list, nested lists, quotations, and multiple heading levels.
- Use shared blue-gray surfaces for code and tables, readable link styling, and local horizontal scrolling for genuinely wide tables/code. Long URLs and unbroken text cannot force the whole dialog or document pane wider.
- Reach the design document's contrast targets in both schemes; quiet metadata and related-document links remain legible. Focus and links remain distinguishable without color alone.
- Preserve sanitization, blocked link/image indicators, frontmatter visibility, and all authored content. Apply equivalent reading styles to ticket and document contexts without leaking CSS into board cards.
- Record the content styling contract for the future formatted editor; implement no editor engine, serialization changes, or rich-text saving.

## Implementation pointers
markdown.css, components/MarkdownBody.tsx, theme.ts, and title/metadata presentation in TicketDetailModal.tsx and DocumentsView.tsx. Coordinate file ownership with the detail and Documents layout tickets. Existing editor ticket: `b217a95f-dc62-4319-b3a1-5c649fe183d9`.

## Handoff
Branch `feature/review-changes-diff`, uncommitted, in the same working tree as 5be60610 (Done) and db7cff48 (links, Verification), which touched the same files first.

**What changed:**
- `markdown.css` rewritten around `--md-*` reading tokens scoped to `.markdown-body`:
  - Scale: 15px prose at line height 1.6 and a 72ch measure. Document headings 22/18/16px. In the ticket dialog they step down to 17/16/15px, so the 20px ticket title stays the largest text. h4–h6 are kept at prose size, muted.
  - Spacing: roomier list, nested-list, paragraph and quotation spacing.
  - Surfaces: blue-gray backgrounds for inline code, code blocks, and table headers and stripes.
  - Links: underlined in both schemes (thicker on hover) with a focus ring, so they don't rely on color. Headings reached by a link show a focus ring for keyboard users.
  - Overflow: code blocks and tables scroll inside themselves, and long unbroken text wraps.
  - Blocked links use a darker orange that passes 4.5:1.
- Quiet metadata: Mantine's `dimmed` grey failed 4.5:1 (about 3.3:1 light, 3.5:1 dark). A `ps-reading` class on the ticket dialog and the Documents view overrides it there only (`#5f6673` / `#a3a9b4`). The board keeps Mantine's value.
- No change to sanitization, blocked-link/image indicators, frontmatter display, authored content, `theme.ts`, or the editor. `MarkdownBody` is used only by the document reader and the ticket dialog, so nothing reaches board cards.
- Docs: "Reading styles as built (2026-09-24)" in `docs/ui-ux-design-direction.md` records the token table as the content styling contract for the future editor (b217a95f).
