# Deploy previews, production deployment, and rollback for the website

## Intended outcome
Every pull request touching the site gets a private preview, and production deploys only from `main`, with a working way to return to the previous build.

## Acceptance criteria
- Pull requests that change `apps/website` produce a preview URL, and preview pages are marked `noindex` and visibly labelled as previews.
- Production deploys from `main` only, and only after the site build and checks pass; a failed deploy leaves the previous site serving.
- Rolling back to the previous production build is done once, as a rehearsal, and the steps are written down.
- No deploy token, repository credential or draft release asset appears in site output or logs; secrets live in the host or CI secret store.
- The production domain serves over HTTPS, and the host-default domain redirects to it.

## Notes
Spec §5 and §9. The user owns DNS changes and any account creation with the host. Keep production deployment switched off (or password-protected) until the launch ticket; the preview is private until then.
