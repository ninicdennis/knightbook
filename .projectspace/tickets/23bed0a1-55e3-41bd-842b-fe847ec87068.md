# Deploy previews, production deployment, and rollback for the website

## Intended outcome
Every pull request touching the site gets a private preview, and production deploys only from `main`, with a working way to return to the previous build.

## Acceptance criteria
- Pull requests that change `apps/website` build a preview of the site in CI and keep it as a downloadable workflow artifact (GitHub Pages has no preview URLs, D-044). Preview pages are marked `noindex` and visibly labelled as previews.
- Production deploys to GitHub Pages from `main` only, and only after the site build and checks pass; a failed deploy leaves the previous site serving. It stays switched off until launch.
- Rolling back to the previous production build (re-running the deployment for the earlier commit) is done once, as a rehearsal, and the steps are written down.
- No deploy token, repository credential or draft release asset appears in site output or logs; secrets live in the host or CI secret store.
- The production domain serves over HTTPS, and the host-default domain redirects to it.

## Notes
Spec §5 and §9. The user owns DNS changes and any account creation with the host. Keep production deployment switched off (or password-protected) until the launch ticket; the preview is private until then.

## Handoff (2026-10-21)

### What changed
- `.github/workflows/website.yml`: on a pull request touching the site, a preview build kept as the `website-preview` artifact (14 days). On `main`, the website's typecheck and tests, then, only if the repository variable `DEPLOY_WEBSITE` is `true`, the production build (refuses drafts) and a GitHub Pages deployment in a separate job with `pages: write` and `id-token: write`. No stored secrets; actions pinned to commit SHAs like `ci.yml`.
- Every non-production page has `noindex, nofollow` and a "Preview build. This is not the published Knightbook website." note.
- README "The website" section: how to view a preview artifact, how deployment is switched on, and how to roll back (re-run the run for the earlier commit).
- D-044 in the specification and a "Deployment" entry in the technical design.

### How it was checked
- Website suite with Chromium: 156 passed, including axe at both widths with the new preview note. Website typecheck clean, Prettier and Oxlint clean.
- New tests: `layout.test.ts` checks every built page of a preview build has the noindex meta and the preview note. `deploy-workflow.test.ts` checks the production condition needs main, not a pull request, and `DEPLOY_WEBSITE`; deploy needs the build job and its production output; the production build sets the production stage and comes after the tests; a pull request's build goes to an artifact, not Pages; no `secrets.`, no `pull_request_target`, read-only by default, Pages write only in the deploy job.
- actionlint (1.7.7) found nothing in `website.yml` beyond not understanding YAML anchors, which `ci.yml` already uses on GitHub.
