# Sign the Windows and macOS builds and notarize the macOS app

## Intended outcome
Released installers open without the unsigned-app warnings: Windows SmartScreen does not flag the installer as unknown, and macOS Gatekeeper opens the app without a workaround.

## Acceptance criteria
- A decision is recorded on which signing route each platform uses (for Windows, for example, a certificate or a cloud signing service; for macOS, a Developer ID certificate and notarization), with its cost.
- The release workflow signs the Windows installer and the macOS app, including the bundled Node helper, and notarizes and staples the macOS DMGs.
- Signing secrets are available only to the trusted release job, never to pull-request runs or forks.
- A build without signing credentials still fails clearly instead of silently publishing an unsigned release once signing is required.
- On a clean machine, the Windows installer and both macOS builds open without the unsigned warnings, and MCP still starts with the app closed.
- The getting-started and installation guides drop any "open the unsigned app" steps.

## Notes
Created 2026-10-01. The first releases ship unsigned by the user's choice, so the release workflow (ticket 356c7683) can go ahead without certificates. Signing needs accounts and certificates only the user can obtain, such as an Apple Developer membership. Code signing and notarization are named as still open in D-028.
