# Write the README, contributing and security files for a public repository

## Intended outcome
Someone who lands on the public GitHub repository understands what Knightbook is, where to download it, what the license allows, and how to report a problem or a vulnerability.

## Acceptance criteria
- `README.md` opens for a visitor, not only a developer: one line on what Knightbook is, a link to the website and download page, and a short License section naming the chosen license and linking `LICENSE`. The developer setup it has now stays, below that.
- `CONTRIBUTING.md` says whether outside pull requests are accepted and on what terms (for example sign-off under the DCO, or a CLA if the license needs one), points to `AGENTS.md` for the working rules, and to the support destination for questions.
- `SECURITY.md` says how to report a vulnerability privately (GitHub private vulnerability reporting, or an address) and that only the newest release gets fixes.
- Each `package.json` carries a `license` field matching `LICENSE`, so tools that read it report the right terms.
- Links resolve, and the text matches the decisions recorded in the specification.

## Handoff (2026-10-21)

### What changed
- `README.md` opens with what a visitor needs: free under the FSL, installers on the GitHub releases page, issues for problems and SECURITY.md for vulnerabilities. A License section at the end summarises FSL-1.1-ALv2 and links `LICENSE.md`. "Getting started" now says it is for building from source. The documents table lists CONTRIBUTING and SECURITY, and no longer calls release automation "a proposal; not enabled" (it is D-040).
- `CONTRIBUTING.md`: issues for questions and problems; open an issue before a pull request (typo and link fixes excepted); contributions are licensed under the project's license (inbound = outbound); AGENTS.md as the working agreement; `pnpm check`; Conventional Commit titles.
- `SECURITY.md`: report through GitHub private vulnerability reporting, newest release only, scope (app, MCP server, release workflow), and that an AI provider's handling is outside it.

### How it was checked
Read against D-043, the issue templates (c125336d) and AGENTS.md. Prettier check passes. Every criterion is about prose, so it is settled by reading; the verifier was not run.

### Not verified
- The README links to the releases page, the issue chooser and the advisory form resolve only once the repository is public.
- `package.json` `license` fields are **not** added. `package.json`, `apps/desktop` and `packages` are release paths (D-041), so the change would publish a new app version with nothing else in it. Add them with the next app change instead (for example b411cc60), as `"license": "FSL-1.1-ALv2"` in each.

### For you to check
- Contribution terms: inbound = outbound under the FSL means you could not later relicense outside contributors' code on other terms without asking them. If you want that freedom, ask for a CLA instead, or do not accept outside pull requests.
- The website domain is not chosen yet, so the README points at GitHub Releases rather than the site's download page. Swap that link in once the site is live.
