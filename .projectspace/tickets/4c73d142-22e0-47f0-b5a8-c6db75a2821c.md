# Board visual pass

## Intended outcome
The board reads as three separated layers with a clear order of importance, so a
person can scan a column without stopping to parse every card. Nothing that the
specification requires to stay visible is removed to achieve it.

## Acceptance criteria
- The window, a column, and a card each have a visibly different background. Borders
  are reserved for the next ticket, the active drop target, keyboard focus, and
  blocked work, not used on every layer at once.
- A card's title has room to breathe, and its status badges sit in one consistent
  footer rather than a vertical stack that pushes the title around.
- "Next up" is the strongest accent on the board.
- An empty In progress column says how work starts there; an empty Verification
  column says finished work waits there for the user's acceptance.
- Done shows a few of the most recent completions with a control that reveals the
  rest, and its total stays visible while collapsed. If a hidden card carries no
  attributable completion decision, the control says so, because that state must
  never be silently hidden (D-005).
- Column headings, ticket titles, and the project path form a readable hierarchy;
  badges are not uppercase by default.
- Both colour schemes are checked at a narrow and a wide window width.

## Notes
Raised by the user after looking at a real board: cards were the same colour as
their column and close to the window background, badges competed with titles, and
thirteen Done cards drew more attention than the active work.

Depends on the settings ticket only because the light scheme has to exist before
this can be checked in it.

## Handoff
**What changed:**

- `src/renderer/surfaces.css` (new) — the three layers as CSS custom properties
  for both schemes: window, column, card, plus a quieter pair for Done and a
  hairline. The shades carry a slight blue cast towards the accent, which is what
  answers "lacking a little bit of colour". The two window backgrounds are
  repeated in `src/main/window-theme.ts` and the file says so, because the native
  window is painted before any stylesheet exists.
- `src/renderer/components/BoardColumn.tsx` (new) — the column, split out of
  Board. It has no outline of its own now; a status dot and a plain heading
  replace the tiny uppercase label, and the count is plain text rather than a
  badge. `EmptyColumn` moved here and its copy changed: In progress says "Choose
  a Backlog ticket to begin", Verification says finished work waits there until
  you accept it, Done says only you can move work there. The Backlog case that
  distinguishes "nothing eligible" from "nothing left" is untouched.
- `src/renderer/components/TicketCard.tsx` — the title is read first, at 1.5 line
  height, and every badge moved into one wrapping footer row instead of a
  vertical stack that pushed titles out of line. Borders now mean something:
  accent for the next ticket (with a 4px left edge), orange for blocked, and a
  hairline otherwise. Next up is a filled accent badge, the strongest thing on
  the board. Unreviewed and Waiting on N became quiet default badges; the
  warning colours are kept for blocked and unattributed. Done cards use the
  quieter surface and a lighter title weight.
- `src/renderer/done-order.ts` (new) + `Board.tsx` — Done is collapsed to the
  four most recent completions with "Show all N". The column count is always the
  full total. A completion with no recorded date is ordered last rather than
  given an invented position, and if any hidden card is unattributed the toggle
  says how many, because that state must never be silently absent (D-005).
- `src/renderer/theme.ts` — Badge labels are no longer upper-case with letter
  spacing, which is most of what made the board feel dense.
- `ProjectHeader.tsx` — the checkout path is quieter.
- `preview/stub-api.ts` — four more Done tickets so the preview shows a
  collapsed Done, which is how a real board looks.

**How it was checked:** `pnpm check` passes (lint, format, typecheck, 245 tests).
Six new tests in `Done.test.tsx` cover the ordering, the hidden counts, the
expand and collapse, and that a hidden unattributed card is announced and keeps
its flag when revealed. One new test in `App.test.tsx` covers the empty-column
copy, which the preview's stub data never shows.

Reviewed by eye in `preview:board` in both schemes at 1280 and 760 wide.

**Not verified:**
- Not seen in the packaged app, only in the browser harness.
- Dragging a card between columns was not exercised; the drop-target styling
  moved from `Card` to `Box` in the new column, so the outline that appears while
  dragging is the one thing worth a deliberate look.
- No keyboard pass over the new "Show all" control.
- Judgement calls you may disagree with: four as the collapsed Done count;
  ordering Done by completion date rather than leaving it in file order; dimming
  Done card titles.

**For you to check:** Your own board, which has thirteen Done cards, in both
schemes. Whether Next up now reads as the strongest thing on it, whether Done is
quiet enough, and whether the collapsed Done hides anything you would rather see.
Then drag a card between two columns and watch the drop target.

## Brought up to date with main
This work was started from c401c92, which was three commits behind `origin/main`
and so did not contain PR #7, the MCP status footer. It has since been replayed
on top of `origin/main` (201ee73). The footer was never removed by this work; it
was simply absent from the tree it was written against.

Four files needed a decision:

- `components/ProjectHeader.tsx` — PR #7 removed `CopyMcpConfig` from the header
  because MCP moved to the footer. That removal is kept, and the settings icon
  this branch added sits where it was. The header is now the project switcher,
  identity, the view control, Refresh and Settings.
- `shared/contract.ts`, `preload/index.ts`, `test-fixtures.tsx` — both sides
  added to the same lists. Both kept.
- `preview/stub-api.ts` merged with no conflict.

**A layout bug the footer exposed**, fixed here on your instruction: the board
subtracted a guessed number of pixels from the viewport
(`calc(100vh - 230px)`) to size a column's scrolling list. PR #7 added a 32px
footer without changing that number, so a full column ran about 32px behind the
status bar. The guess is gone: the list is now `flex: 1` inside a column that is
already stretched to the row, so it takes whatever is left under the heading
whatever else claims vertical space. The `shortened` prop that made the same
guess for the record-problems banner is gone for the same reason — flexbox
already accounts for it.

**Checked after the replay:** `pnpm check` exits 0, 283 tests across the
workspace, including PR #7's own `McpFooter`, `mcp-status` and `mcp-sessions`
suites. In the preview at 1280x860, with the problems banner showing and Done
expanded to all seven cards, in both schemes: the footer reads "MCP connected",
the banner renders, and the longest column ends above the footer instead of
running behind it.
