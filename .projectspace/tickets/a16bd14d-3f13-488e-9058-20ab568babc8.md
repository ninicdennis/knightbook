# Group Documents into collapsible folders with custom titles

## Intended outcome
The Documents sidebar shows a readable nested folder hierarchy, with optional names such as Documentation for docs, so users can collapse sections and quickly find files.

## Acceptance criteria
- Derive nested folder groups from the real paths of included Markdown files. Root files remain directly accessible; distinguish duplicate basenames through their path context.
- Let the user assign, edit, and clear an optional title for each folder, including nested folders. Persist titles in project-local repository-owned metadata keyed by normalized project-relative folder path. A label never renames or rewrites the source folder/files.
- Expand/collapse groups independently and retain expansion appropriately per project as local view state. Selecting a document or following an internal link makes its location discoverable, including when ancestors were collapsed.
- Preserve documents_include, includedVia, overlap deduplication, exact removal scope, review status, external editing, and canonical path resolution. Collapse is never removal, and removal of inclusion never deletes source files.
- Handle missing files, unreadable paths, and stale labels after external folder renames visibly and without destructive cleanup. Validate metadata paths using existing project-boundary rules.
- Provide keyboard-accessible tree navigation, visible focus/selection, named expand controls, and expanded/selected state for assistive technology. Evaluate Mantine Tree already available in the UI stack before writing custom tree behavior.
- Reuse the Board palette and coordinate with the existing Documents responsive-layout ticket. Verify labels and long paths in both themes, narrow views, and zoom.

## Handoff
**What changed:** *Core:* `packages/core/src/folder-titles.ts` adds `listFolderTitles` and `setFolderTitle(project, folder, title | null)`. Titles are a sparse `folder_titles` map in `.projectspace/project.md`, keyed by normalized project-relative path and edited key by key through the YAML document, so unknown fields survive. A title must name an existing folder inside the project (same boundary rules as inclusion) and be at most 80 characters. A missing folder is reported `missing: true` and kept until cleared. A malformed map reads as no titles, and writing over it is refused. *MCP:* `documents_list` returns `folder_titles`, and the skill explains them. Setting them is app-only. *App:* the Documents list is now a tree built from paths (`document-tree.ts`), with folders first, then files. Each folder is a button with `aria-expanded`/`aria-controls` and shows its title beside its real name. A pencil button labelled "Name the folder <path>" opens `FolderTitleDialog`, which has Save and Clear title. Collapsed folders are kept per checkout in the window's local storage, never in the project. Selecting or linking to a document opens every folder above it. Titles for missing folders are listed under the tree with an explicit Clear. Document rows no longer repeat their path, since the folder shows it; the full path is on hover. *Mantine Tree:* evaluated and not used. 9.6.1 sets no `aria-expanded` on nested nodes, ignores Enter, and keeps only the first node tabbable. The disclosure pattern is used instead. The reasoning is in the technical design under "Document folders and their titles as built".
**How it was checked:** `folder-titles.test.ts` (core) covers round trips including nested folders; inclusion, listing and files unchanged; clearing to no map; unknown metadata kept; a folder renamed outside the app reported missing and still clearable; refusals (missing folder, a file, outside the project, reserved folder, empty or overlong title); and a malformed map read as none and refused on write. `DocumentFolders.test.tsx` covers nesting and titles, collapse/expand with stored state, auto-expanding ancestors of the selected document, keyboard Enter/Space, naming, clearing, a refused save keeping the dialog, stale titles cleared only on click, sort order with same-named files, and ancestor paths. The existing Documents, layout, links and review-changes suites pass with the tree. `pnpm check` passed.
