# A Documents workspace that fits the window

## Intended outcome
Documents use the board's layered surfaces and retain usable navigation, reading space, and actions on shorter or narrower windows.

## Acceptance criteria
- Use a quiet document-navigation panel and a distinct raised reader, with the same purposeful borders, spacing, and selection treatment as the board.
- Replace fixed sidebar/nowrap assumptions with a deliberate narrow layout, such as an accessible document-list drawer with a clear return control. Keep the selected document and full path identifiable.
- Keep document identity, review state, Read-only status, review action, and Edit externally reachable in a responsive toolbar, while the document body scrolls independently.
- Size navigation and reader from their actual available container height instead of calc(100vh - 140px/260px), accounting for header, MCP footer, alerts, frontmatter, and include controls. The last document and last prose line remain reachable.
- Make include-files/folder controls discoverable but subordinate to reading. Preserve exact removal scope explanations, selected-document behavior, and non-destructive inclusion semantics.
- Provide coherent empty, loading, missing-file, and read-error states with existing recovery actions; do not hide record problems for visual tidiness.
- Preserve document links, review behavior, external editing, and sanitized read-only rendering. The content region must accept the future editor without implementing it here.

## Handoff
**What changed:** (branch `feature/unified-app-shell`, uncommitted, on top of the shell ticket `d23f787f`)
- `DocumentsView.tsx` was split up:
  - `DocumentNav.tsx` holds the list and the include controls.
  - `DocumentReader.tsx` holds the toolbar and the scrolling body.
  - `DocumentsView.tsx` keeps the state and the layout.
  - Styles are in the new `documents.css`.
- **Surfaces:**
  - The navigation panel is on the column layer, like a board column. The selected document is raised onto the card layer (`aria-current`) and set in semibold.
  - The reader is a raised card.
  - "Included from" is now sentence case, not spaced capitals.
  - Muted text uses `--ps-text-muted`.
- **Heights:** no `calc(100vh - …)` is left. The panels are grid and flex children with `min-height: 0`, and only the list, the include section (capped at 35% of the panel) and the reader body scroll. In `App.tsx` the views now sit in a `flex: 1; min-height: 0` box, so an app-level alert takes space from the view instead of pushing it past the footer. The board is inside the same box and looks unchanged.
- **Narrow layout (under 48em, 768px):**
  - The list and the reader take turns.
  - Choosing a document opens the reader and moves focus to its title.
  - "All documents" goes back and moves focus to the same list item.
  - Opening a document from a ticket link goes straight to the reader.
- **Short windows (under 30em, 480px tall):** the whole reader scrolls, toolbar included, so the body gets the full height.
- **Toolbar:** title, full wrapped path, review badge, Read-only, Mark reviewed and Edit externally. It wraps instead of clipping. The list shows each path truncated from the start, with the full path in the DOM and in `title`. A review hint ("Not reviewed" / "Changed since your review") replaces the unlabeled icon.
- **States:** the list failing to load now shows its own error with Try again. It no longer shows the "No documents included yet" screen. A document failing to open shows its own error with Try again, and loading shows a spinner in the reader. Action failures and refresh failures appear above the body; a failed refresh keeps the last list and says so. Missing manifest entries still show "no longer exists". The empty state and all include/remove wording are unchanged.
- **Preview:** new `preview/documents-stub.ts`, driven by `?docs=many|none|list-error|read-error`.

**How it was checked:**
- `pnpm check` passes: lint, format, typecheck, all suites (desktop 274 passed, 1 skipped). The existing `Documents.test.tsx` passes unchanged.
- New `DocumentsLayout.test.tsx` covers: list failure with retry, document failure with retry, the selected marker and review hint, and the narrow switch with focus moves.
- **Before the change** (preview, 900×650): the reader fit only because flex shrink held it. The list was capped at `calc(100vh - 140px)` no matter what else was in the panel, so a long list could push the include controls below it.
- **After the change**, with 26 documents at 1280×860 and 900×650:
  - No page scroll.
  - The last list item and the last line of prose scroll into view inside their panels, above the footer.
  - The include section stays visible.
- At 450×325 (a 900×650 window at 200% zoom, run in an iframe): no sideways scroll, the list and reader take turns, focus moves as described, and the reader scrolls down to its last line.
- In the browser:
  - Tab goes from the toolbar into the document content, and Page Down scrolls the body.
  - Light and dark screenshots were checked.
  - The error and empty states were viewed in light.
- Found and fixed along the way: absolutely positioned hidden labels escaped the list and made the page 900px taller.

**Not verified:**
- Not run in the Electron window, and not packaged.
- Real browser zoom was not tested; 200% was simulated by size only. Mobile emulation in the preview pane does not apply (the page has no viewport meta tag), so narrow widths were tested in an iframe.
- Documents with no links or code blocks were not keyboard-tested. They should rely on Chromium making the scroller itself focusable, which is why the body has no `tabIndex`.
- Contrast was reasoned from the `--ps-text-muted` values against these layers. It was not re-measured for every Documents text.
- macOS/Linux were not checked.
- `App.tsx` is now 307 lines, over the ~300 ideal. Moving the view switch out would bring it down.

- Decide whether letting the whole reader scroll on very short windows (toolbar scrolls away) is acceptable.
