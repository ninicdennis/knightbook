# Typecheck the board preview

## Intended outcome
`pnpm preview:board` serves the same shapes the app's host does, and a contract change that the preview's stub does not follow fails the typecheck instead of going unnoticed.

## Acceptance criteria
- `apps/desktop/preview/` is included in the desktop package's typecheck.
- The stub API implements every member of `KnightbookApi`, including `archiveTickets` and `restoreTicket`, and its board data carries `archivedAt` and `archivedTickets`.
- The preview's Archive tab opens with the stub data and archiving or restoring a card in it does not throw.
- No shipped code changes.

## Notes
Found on 2026-09-22 while splitting `stub-api.ts` (ticket 9ca4698b). `apps/desktop/tsconfig.json` includes `src`, `scripts` and `electron.vite.config.ts` but not `preview`, so the stub drifted when the Archive feature (PR 15) added `archivedAt` to `TicketView` and `TicketSearchHitView`, `archivedTickets` to `ProjectView`, and `archiveTickets`/`restoreTicket` to the API. A one-off typecheck reported four errors, all of that kind.

## Handoff
**What changed:** (uncommitted, branch `feature/easy-wins`)
- `apps/desktop/tsconfig.json` now includes `preview`, so the desktop typecheck (and `pnpm check`, and CI) cover the stub from now on.
- `preview/stub-api.ts`:
  - `ticket()` defaults `archivedAt: null`.
  - The stub project carries `archivedTickets` with one sample card, so the Archive tab has something to show.
  - `archiveTickets` and `restoreTicket` are implemented. They record the call and return the fixed board, like every other stub operation.
- `preview/ticket-search-stub.ts` passes `archivedAt` through on search hits.
- No shipped code changed.

**How it was checked:**
- Desktop typecheck is clean with `preview` included. Before the fix, a one-off typecheck of `preview/` reported the four errors described in the notes.
- In `pnpm preview:board`, the Archive tab opened showing the sample card, and Restore fired `restoreTicket`. Archive from a card menu fired `archiveTickets` with that card's id and revision. No console errors.
- Desktop tests 266 plus the existing skip; Prettier and Oxlint are clean.

**Not verified:** the stub's board does not change after archiving or restoring, because it is fixed data. That matches how the stub handles every other mutation, and it is not something this ticket set out to change.

**For you to check:** run `pnpm preview:board`, open the Archive tab, and try Restore and a card's Archive.
