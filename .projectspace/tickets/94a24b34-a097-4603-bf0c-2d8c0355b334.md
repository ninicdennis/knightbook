# Split the MCP ticket tools

## Intended outcome
`packages/mcp/src/tools.ts` is back under the project's 400-line hard limit, with the tools that record the user's decisions about a ticket in a file of their own.

## Acceptance criteria
- `packages/mcp/src/tools.ts` is under 400 lines, and no file extracted from it exceeds 300.
- The decision tools move together: `ticket_record_user_completion`, `ticket_record_verification_issue`, `ticket_resolve_verification_issue`, `ticket_archive` and `ticket_restore`. They are the ones that record or undo a decision rather than edit content.
- This is a rearrangement: tool names, input schemas, descriptions and responses do not change, on both the root-bound and the shared connection.
- Every existing test passes unchanged, including the guidance-drift test that checks the skill against the registered tool list.

## Notes
`tools.ts` was 439 lines before the shared MCP connection (43253b7e) and grew to 557 with that work and the archive tools. Found while reviewing the board for tech debt on 2026-09-22. Other files a little over the limit (`ipc.ts`, `tickets.ts`, `contract.ts`, `preview/stub-api.ts`) are out of scope here.

## Handoff
**What changed:** (uncommitted, branch `feature/easy-wins`)
- `packages/mcp/src/ticket-decision-tools.ts` (188 lines) now holds the five decision tools: `ticket_record_user_completion`, `ticket_record_verification_issue`, `ticket_resolve_verification_issue`, `ticket_archive` and `ticket_restore`.
- **One step beyond the criteria:** moving only those five would have left `tools.ts` at about 405 lines, still over the limit. The shared ticket description (`indexTickets`, `summarize`) therefore also moved, into `ticket-summary.ts` (90 lines).
- `tools.ts` is now 328 lines.
- `registerTools` calls `registerTicketDecisionTools` itself, so the server, the guidance-drift test and every other caller still get the full tool set from one call. The only visible difference is that `tools/list` now shows the decision tools after `ticket_reorder_backlog` instead of among the other ticket tools. Order is not part of the contract.

**How it was checked:**
- A script compared the original file with the new ones: all 13 tool registrations and both helpers appear byte-for-byte. Names, schemas, descriptions and handlers are unchanged.
- No existing test was changed.
- Suites: core 185, MCP 40, desktop 266 plus the existing skip. The packaging suite passed 47 against the rebuilt bundle, which includes the shared-connection end-to-end tests over real stdio.
- Typecheck is clean in all five packages, and Prettier and Oxlint are clean.

**Not verified:** the packaged app was not rebuilt.

**For you to check:** read `ticket-decision-tools.ts` and confirm the grouping reads well to you. `ipc.ts`, `tickets.ts`, `contract.ts` and `preview/stub-api.ts` are still a little over 400 lines and were left out of scope.
