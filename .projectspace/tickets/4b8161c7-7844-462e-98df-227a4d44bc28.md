# Packaged-app smoke test

## Intended outcome
Catch regressions in the real Electron window, which no current test touches.

## Acceptance criteria
- A Playwright Electron test launches the packaged app, opens a fixture project, moves a card, and asserts the result on disk.
- A keyboard-only pass over the card menu and the completion dialog.

## Notes
Design section 2 calls Playwright's Electron support experimental. A screenshot of the packaged window could not be captured in the environment used so far.

## Handoff
**What changed:**
- `experiments/packaging/src/packaged-window.test.ts` (new): launches the packaged Electron binary with Playwright, opens a fixture project, moves a card through the card menu, and asserts the new status in the ticket's own `.md` file. It also captures a screenshot of the running window and asserts the file is non-empty, which the Notes above said could not be done before.
- `experiments/packaging/src/packaged.ts` (new): packaged-build discovery shared by both packaged-app suites, extended to find the launchable binary. Everything stays discovered rather than written down, for the reason the old comment gave: spelling the macOS bundle name out is what let the suite silently stop checking after the rename.
- `experiments/packaging/src/packaged-app.test.ts`: now imports that discovery instead of carrying its own copy. No test changed.
- `apps/desktop/src/renderer/Keyboard.test.tsx` (new): six tests that touch nothing with a pointer. Tab to the card handle, Enter to open, ArrowDown to the item, Enter to activate; then the same route into the completion dialog, Tab to its confirming button, Enter to record. Escape is asserted to record nothing, on both the menu and the dialog.
- `experiments/packaging/package.json`: adds `playwright-core` (not `playwright`, which downloads three browsers on install that driving Electron never uses).
- `.github/workflows/ci.yml`: the packaged-app step is split by platform, because the Linux runner has no display and Electron needs one. Linux now installs and runs under `xvfb`.

**How it was checked:**
- `Keyboard.test.tsx`: 6/6 pass. I also confirmed it is not vacuous — pointing the menu walk at a label that does not exist fails with `No menu item called "…". The menu offers: View details, In progress, Verification, Mark content reviewed.`, so the ArrowDown navigation is genuinely reaching items.
- Full desktop suite after the change: 232 passed, 1 skipped, 25 files, no unhandled errors.
- `packaged-app.test.ts` after the refactor: 3/3 pass, and they *ran* rather than skipped, which means the new executable discovery resolved. Printed directly, it finds `apps\desktop\release\win-unpacked\Knightbook.exe`.
- Desktop `tsc --noEmit`: clean. `oxlint`: clean. `prettier --check` on every file touched: clean.

**Not verified:**
- The Linux `xvfb` CI step is untested; I cannot run GitHub Actions.
- macOS and Linux executable discovery is unexercised — only the Windows branch ran. The macOS branch reuses the existing, previously-working bundle search; the Linux branch is new code.
- The window test asserts the *card menu* path only. Drag-and-drop is still untested by anything, on purpose: it is pointer-only and the menu performs the same moves.

**For you to check:**
1. `pnpm --filter @knightbook/experiment-packaging test` — 31 tests, all passing here, including the three window tests.
2. The screenshot is written to a temp dir and deleted with it. If you want to look at it, comment out the `rm` in `afterAll`.
3. Confirm you are happy with `xvfb` being installed inside the CI job rather than pinned in a container image.

## Correction after the first run
The first version of the move test used `getByRole('button', { name: 'Actions for …' })` without `exact`. Playwright matches an accessible name as a **substring** by default, and dnd-kit wraps every card in a `role="button"` draggable whose name is composed from the card's contents — so it contained the menu button's own label and matched as well. That is a strict mode violation, not a mis-click. Both role locators in that test now pass `exact: true`, with a comment saying why, since it is the kind of thing that gets tidied away later.

With that fixed the whole suite passes. I also confirmed the test is not vacuous: pointing it at a menu item that does not exist makes it wait 30 seconds for that item and then fail, so the menu genuinely opens and Playwright genuinely drives the live window.
