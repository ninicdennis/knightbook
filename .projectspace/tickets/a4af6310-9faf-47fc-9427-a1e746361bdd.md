# Audit the repository before it is made public

## Intended outcome
Nothing in the repository, its history or its settings would be a problem once anyone can read it, and anything that is gets fixed or knowingly accepted by the owner before the switch.

## Acceptance criteria
- Every commit on every branch is scanned for secrets (API keys, tokens, private keys, `.env` files) with a dedicated scanner such as gitleaks, not only a grep, and the result is recorded here. Any finding is rotated first, then removed.
- Commit author names and emails across history are listed, and the owner confirms each is fine to publish. (2026-10-21: two identities, `Denny <…users.noreply.github.com>` and `doggobot <40923967+ninicdennis@users.noreply.github.com>` on 98 commits.)
- Tracked files contain no personal paths, client names or private project content. Test fixtures with placeholder paths (`/home/you`, `C:\Users\Ada Lovelace`) are fine.
- `.projectspace/`, `docs/` and the website's interim screenshots are checked for anything the owner would not want public, since the board and internal docs become readable too.
- Large or binary files in history are listed with their sizes, so the clone size is known.
- The workflows are checked for what a fork pull request can do once the repository is public: no `pull_request_target`, no secrets reachable from pull-request runs, and the release job runs only on `main`.
- Any history rewrite is the owner's decision and is not done without it.
