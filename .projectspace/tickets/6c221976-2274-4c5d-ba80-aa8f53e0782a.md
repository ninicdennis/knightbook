# Document site rollback, download withdrawal, and the per-release site update

## Intended outcome
A maintainer has written procedures for publishing a release to the site, withdrawing a bad download, and rolling the site back, and each has been rehearsed once.

## Acceptance criteria
- A per-release checklist in the repository follows the spec §5 order: validate binaries, publish the release, check the public downloads (URL, size, checksum, no login), update the release-data file, notes, compatibility table, affected guides and screenshots, then deploy.
- A withdrawal procedure marks a release as withdrawn in the release-data file, names a known-good release or shows temporary unavailability, and was rehearsed against a preview deploy.
- A rollback procedure returns production to the previous build and was rehearsed once; the steps match what the deploy ticket set up.
- The README or maintainer docs link to all three.

## Notes
Spec §5 and §10 launch criteria. This is maintainer documentation in the repository, not a public page.
