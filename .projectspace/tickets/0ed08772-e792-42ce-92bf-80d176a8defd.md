# Write the connecting-an-AI-tool guide, tested with one named client

## Intended outcome
`/docs/connecting-ai/` gets a user from the installed app to a working MCP connection in at least one named client, following steps that were actually tested.

## Acceptance criteria
- Explains MCP as optional, the bundled server, and the workflow skill as separate setup steps: tools give capabilities, the skill teaches the workflow.
- Uses the configuration copied from the installed app as the source of paths. There is no hard-coded developer checkout path, and no Windows command shown for other platforms.
- At least one client (for example Claude Code, Codex or OpenCode, which the app can already copy configuration for) is tested end to end: add the configuration, restart, run the read-only check prompt, and read the same project after closing the desktop window.
- Each client section records the app version, client version and test date.
- Covers one connection per project root, several local checkouts of the same project, moving a project, reconnecting after an app update, and working with the window closed.
- States that a "connected" indicator does not prove the client follows the workflow skill.
- Clients that were not tested are not named as supported.
