Pull-request CI took 7 to 11 minutes. Nearly all of it was `pnpm check` on one 4-core Linux runner, where the desktop and website test suites ran at once and slowed each other down (401 s and 214 s there, about 147 s each alone). Decision D-050.

## Acceptance criteria

- On a pull request, `check` runs as three Linux jobs at once: the desktop tests, the website tests, and lint, format check, typecheck and every other package's tests.
- Together the three run every command `pnpm check` runs, and a new package's tests are included without editing the workflow.
- Only the website job installs Chromium, and it still sets `REQUIRE_WEBSITE_BROWSER`.
- `package` still starts only after every `check` job has passed.
- Releases and manual runs are unchanged: one `check` per platform running `pnpm check`.

## Handoff

**What changed**

`.github/workflows/ci.yml`: `check` gains a `part` matrix dimension. Pull requests get `desktop`, `website` and `the rest`; every other trigger gets `all`, which runs `pnpm check` exactly as before. `package` reuses the platform list through a YAML anchor as before. D-050 in the specification; AGENTS.md and README updated.

**How it was checked**

- Timed each part locally on 4 cores, Node 24, pnpm 12.4.2: desktop tests 147 s, website tests 147 s, lint + format + typecheck about 25 s, the other packages' tests 18 s. All passed.
- The exclusion filter `pnpm -r --filter '!@knightbook/desktop' --filter '!@knightbook/website' test` ran core, mcp and both experiments.
- actionlint 1.7.12 and Prettier pass on the workflow.
- The pull request's own CI run is the end-to-end check of the split.

**Not verified**

- The release path (Windows, macOS) was not run; its matrix resolves to `part: all`, so it runs the same steps as before. A manual CI run would confirm it.
- No verifier run: the change is a workflow file and has no unit test to trace.

**For you to check**

- If "Check (ubuntu-latest)" is a required status check on `main`, it has to be replaced by the three new names.
