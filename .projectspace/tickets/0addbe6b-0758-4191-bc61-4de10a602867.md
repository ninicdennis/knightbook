# Filter each board column by ticket type and state

## Intended outcome
Each column can be narrowed to the tickets the user cares about right now, by type and by state, without affecting the other columns.

## Acceptance criteria
- Every column has its own filter control for type: Feature, Bug, Task and untyped, multi-select.
- The same control filters by state: blocked, waiting on dependencies, ready to start, flagged by a failed prerequisite, and review status (unreviewed, reviewed, changed since review).
- A filtered column shows that it is filtered and how many tickets are hidden, with one action to clear it, so hidden tickets never look missing.
- A column whose filter matches nothing says so, distinct from an empty column.
- Filters are view state only; they never change ticket files or backlog order, and dragging within a filtered Backlog keeps the full order correct.
- Filters are keyboard accessible and work at narrow and wide window widths.

## Notes
Requested by the user on 2026-09-23. Assumption to confirm when this starts: 'states' means the ticket conditions above, since status is already the column itself. Whether filters persist between launches is open; the default proposal is to remember them per project locally, never in project files.

## Handoff
**What changed:** Every column heading has a filter button. It opens three checkbox groups:
- **Type:** all five types (the user chose to include Research and Documentation) plus Untyped.
- **Condition:** Blocked, Waiting on prerequisites, Ready to start, Affected by a failed prerequisite. The two readiness options appear in Backlog only, matching the card badges.
- **Review:** Unreviewed, Reviewed, Changed since review.

A card matches if it matches any ticked box within a group, and every group that has something ticked.

A filtered column shows "Showing X of Y. N hidden by this filter." with **Clear filter**. When nothing matches it says so in words an empty column never uses. Whole-column archiving is hidden while a column is filtered. Filters are remembered per checkout in the window's localStorage (the user's choice), never in project files.

**Move up** and **Move down** in a filtered Backlog now pass the next *visible* card, and still send the whole backlog, so hidden tickets keep their order. This also applies under the plan filter. Reordering is done from the card menu; there is no drag within a column.

Code is in `apps/desktop/src/renderer/board/column-filter/`, plus `Board.tsx`, `BoardColumn.tsx` and `tickets/useTicketActions.ts`. The decision is D-037 in the spec.

**How it was checked:**
- `pnpm check` passes: lint, format, typecheck, every suite. Desktop is 74 files passed and 1 skipped; the skip was there before this change.
- 25 tests in `column-filter/` cover:
  - a leak test: a non-bug in another column stays visible;
  - an empty column with a remembered filter still reads as empty;
  - the singular and plural no-match text;
  - no write operation is called;
  - the full-order reorder;
  - Tab reachability;
  - remembering per checkout.
- The verifier found nothing uncovered. Its weak spots were the leak test, the empty column, "never writes", keyboard via Tab, and the ready/review edge cases; all of those tests have since been added.
- Layout pass in `pnpm preview:board` at 1600px dark and 800px light, including the filter surviving a reload. I removed an indicator dot that crowded the count.
