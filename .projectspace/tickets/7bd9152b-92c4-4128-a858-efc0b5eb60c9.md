# Consistent supporting surfaces

## Intended outcome
Project switching, settings, search results, connection details, and workflow confirmations look related to the board and make their primary action easy to identify.

## Acceptance criteria
- Apply common panel/raised-surface roles, title/body/metadata hierarchy, spacing, and control treatments to existing project switcher, welcome/folder setup, Settings, ticket search, MCP details, and completion/verification dialogs. Avoid a new component framework or unrelated behavior rewrite.
- Present project name before path, selected/current state clearly, and existing blocked-switch explanations next to the unavailable action. Long paths, result titles, and configuration snippets fit through wrapping or local scrolling.
- Keep settings grouped by purpose and selected appearance obvious. Use sentence-case section labels and restrained separators rather than repeated heavily outlined cards.
- Keep MCP status summary scannable; preserve the current separation of runtime, process, and client facts, including polling and stable wording while details are open. Do not introduce Start/Stop controls. Put existing technical details and copy configuration behind clear disclosure without hiding actionable errors.
- Confirmation dialogs clearly distinguish the decision action from Cancel and explain the existing consequences. Keep content review distinct from user completion and retain issue reasons/provenance.
- Match empty, loading, error, disabled, hover and focus treatments; verify overlay focus, Escape, focus restoration, accessible names, and controls fitting at short heights.
- Preserve current search ranking/scope, keyboard behavior, settings persistence, and project-switch safety. Do not build guided setup, shared MCP connections, Archive, or change lifecycle semantics.

## Implementation pointers
Existing overlay components under apps/desktop/src/renderer/components (including ProjectSwitcher, Welcome, SetupFolder, SettingsDrawer, TicketSearch, McpStatusDetails, CopyMcpConfig, CompletionDialog, and VerificationIssueDialog); shell header/footer geometry belongs to the separate shell ticket. ## Handoff
**Scope taken (2026-09-24):** the user asked for modals, the MCP popup and drawers to share the board's colour scheme, so the app looks uniform. This pass does that everywhere. It covers only part of this ticket's hierarchy criteria; see **Not done** below. Branch `feature/unified-app-shell`, uncommitted.

**What changed:**
- `theme.ts`:
  - Mantine's `dark` scale is re-tinted to the board's blue-grey. Every default control, input, border and secondary text in dark mode now follows it.
  - `SegmentedControl` gets the shared classes, so Settings' colour scheme and search scope match the header's view switch.
  - A `cssVariablesResolver`, wired in `main.tsx` and `preview/main.tsx`, changes light mode's `dimmed` to `#5f6673` and its orange/red text to `#b54708`/`#c92a2a`. Those were 3.3:1, 2.6:1 and 3.3:1 on white.
- New `components.css`, using Mantine's static class names so every overlay follows without opting in:
  - Modals, drawers, menus and popovers use the card layer, a hairline border and the new `--ps-overlay-shadow`.
  - Modal and drawer headers get a hairline rule under a 600-weight title, as the ticket detail view already had, and the body padding is restored beneath it.
  - Also here: the shared segmented style (moved out of `shell.css`).
- Project switcher: the open project sits on the column layer in semibold instead of an accent fill, and row borders are hairlines.
- Welcome recent cards are on the card layer with a hairline.
- "Recent", "Connecting an AI tool" and the ticket-detail section labels are sentence case instead of spaced capitals.

**How it was checked:**
- `pnpm check` passes: lint, format, typecheck, all suites (desktop 274 passed, 1 skipped). No tests were added: this pass is styling, and jsdom cannot see colour.
- In `pnpm preview:board` at 1280×860, confirmed by computed style that these use the card layer (`#252932` dark, `#ffffff` light): the MCP popup, both drawers, the search modal, the completion dialog, the ticket detail modal and the card action menu.
- Viewed dark and light screenshots of those overlays. The completion dialog's teal decision button stands clearly apart from Cancel.
- The board looks unchanged after the palette change, including the quiet Done column.
- Contrast audit of every text in the open overlays: the lowest was 4.62:1 (light) and 4.71:1 (dark). Light orange warnings went from 2.57 to 5.43.

**Not done (remaining criteria in this ticket):**
- MCP details were only restyled. Technical details and Copy MCP configuration are not yet behind a disclosure.
- Search result rows and their title/metadata hierarchy were not reworked.
- Blocked-switch explanations were not moved next to the disabled action; they are still an alert at the top of the drawer.
- Focus, Escape and focus restoration were not re-tested by hand. Behaviour code was not changed and the existing tests pass.
- Overlays were not checked at 900×650, 200% or short heights.
- The verification-issue, archive-column and remove-entry dialogs were checked only by class, not by screenshot.
- Welcome was not seen live: the preview always opens a project.
- Light-mode *badges and alert titles* (such as "Blocked" and "Did not pass verification") still use Mantine's lighter orange; only plain text was darkened.

**Not verified:**

- The preview pane often did not paint transitions, so some screenshots showed mid-fade frames. Those checks relied on computed styles instead.
- macOS/Linux were not checked.
