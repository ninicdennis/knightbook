# Releases page listing versions and linking to release notes

## Intended outcome
`/releases/` gives visitors the version history, known issues and compatibility changes, read from the same release-data file as the download page.

## Acceptance criteria
- `/releases/` lists each release, newest first, with version, channel, date and a link to the authoritative release notes.
- Withdrawn releases are shown as withdrawn, with the reason and the known-good release to use instead.
- Known issues and compatibility changes (such as data-format changes that make downgrading unsafe) are shown when a release records them.
- With no releases, the page says so plainly instead of showing an empty list.
- The page reads the release-data file from the download-page ticket; there is no second copy of release facts.

## Notes
Spec §3: the release history may start as a simple index that links to the distribution release notes.

## Handoff

**What changed.** The work is on branch `feature/website-shell`, with the other website tickets, and is not committed yet. A note is in the technical design ("Releases page"). No app paths changed.
- **`apps/website/src/pages/releases/index.astro`** lists every release from `src/download/releases.json`, newest by version number. Each shows its version, a Preview label for a preview, the date, "Stable channel" or "Preview channel", and a link to its release notes. Compatibility changes and known issues appear only when recorded. A withdrawn release gets a Withdrawn label, its reason, and "Use Knightbook X instead" linking `/download/`. X is the release `/download/` recommends; if there is none, the page says "There is no other release to use instead yet." With no releases, it gives one plain sentence instead of an empty list.
- **`release-data.ts`:** a new optional `compatibilityChanges` list, which defaults to empty.
- **`download-view.ts`:** `releaseHistory()` shares the download page's sorting and recommendation, so the two pages cannot disagree.

**How it was checked.**
- `pnpm check` passes. Website: 100 tests, and `astro check` reports 0 errors. Everything else is unchanged.
- **`releases-page.test.ts`** builds the real site from:
  - an explicit empty release list;
  - a history of 0.2.0, 0.3.0 (with a compatibility change and a known issue), 0.3.1 (withdrawn), 0.4.0 (preview) and 0.10.0 (stable), each on a different date;
  - only the withdrawn release.

  It checks:
  - the order 0.10.0, 0.4.0, 0.3.1, 0.3.0, 0.2.0, which is numeric, so a text sort fails;
  - each release's own date, channel and release-notes link, and the Preview label;
  - the withdrawn release points to 0.10.0, the recommended one, not merely 0.3.0, the one below it;
  - the "no release to use instead" case;
  - compatibility changes and known issues shown for 0.3.0 and absent for 0.2.0;
  - the empty sentence;
  - the page reads the shared loader and contains no version of its own;
  - no `<script>`.
- **Browser:** a sample history at 390px dark (screenshot) showed the withdrawn notice, the compatibility changes and the known issues, with no sideways scroll, and Releases marked as the current page in the header menu. The real data shows the empty sentence.
