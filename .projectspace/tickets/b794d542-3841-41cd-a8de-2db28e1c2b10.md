# Write the projects, documents, and portability guide

## Intended outcome
`/docs/projects-and-documents/` explains where a project's data lives, how documents are included, and how to move or share a project safely with Git.

## Acceptance criteria
- Explains what `.projectspace/` holds, which records travel with the project, and that `runtime/` and `.write-lock` are disposable coordination state. It does not tell users to ignore the whole folder.
- Covers including a file or folder (a recorded path, not a copy), folders with custom titles, unresolved paths, removing from the view versus deleting the source file, relative links, in-project images, editing in an external editor, and Refresh or refresh-on-focus.
- Git: users run Git themselves; before a pull, branch switch or restore they should stop active writers and check outstanding edits; conflicts are resolved, not overwritten.
- Does not describe single-session use as real-time team collaboration, or promise sync or backup.
- Every UI action named in the guide exists in the release it targets.
