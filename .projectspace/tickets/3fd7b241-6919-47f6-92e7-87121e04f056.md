# The window says which project is open

## Intended outcome
The title bar and the taskbar entry name the open project and the folder it came from, so the right window is findable without bringing it to the front.

## Acceptance criteria
- With a project open, the window title is the project's name followed by the checkout folder's name. The folder is what separates two clones of the same project, which the name alone cannot do.
- With nothing open, and on the welcome, loading, not-a-project and failed screens, the title is `Projectspace` and claims no project.
- The title follows the project: switching projects, completing one-click setup for a new folder, and a name changed in `project.md` and picked up by a refresh all update it.
- The name comes from the loaded project record, not from the folder name, and is not truncated or reformatted beyond what the operating system does on its own.
- Setting the title is a host concern. The renderer asks through a named operation in `src/shared/contract.ts` like every other host call; it does not reach Electron directly.

## Notes
`apps/desktop/src/renderer/index.html` sets a static `<title>Projectspace</title>` and nothing changes it afterwards. The in-window header already shows both the project name and the checkout path, so this is only about what is visible from outside the window.

The skill that guides AI tools in this project tells them to say which project they are in, because two clones look alike. The window should be able to answer the same question.

## Verification
Open a project and read the title bar and the taskbar entry. Switch to another project and back. Set up a fresh folder and confirm the title changes at the point the board appears. Edit the name in `project.md`, refresh, and confirm it follows. Close the project or start from the welcome screen and confirm the plain title returns. Check a long project name does not break the window controls on Windows.

## Handoff
**What changed:**
- New contract operation `showProjectInWindowTitle(project | null)` in `src/shared/contract.ts`, on IPC channel `window:showProjectInTitle`. It is handled in `src/main/window-title-ipc.ts` and sets the title of the window that asked.
- `src/main/window-title.ts` builds the title as `<name> — <checkout folder>`, joined by an em dash. It checks what the renderer sent: anything but a non-empty name and path gives the plain title. A drive root, which has no folder name of its own, falls back to the full path.
- `src/renderer/hooks/useWindowTitle.ts`, called from `App.tsx`, sends the open project's name and path, or `null` on any other screen. It depends only on those two values, so it follows switching, setup (which ends in the same `load`) and refresh-picked-up renames.
- `index.ts` gives the window the plain title up front and ignores `page-title-updated`, so a renderer reload cannot put the page's `<title>` back over the host's.

**One deviation:** The plain title is `Knightbook`, not `Projectspace`. This ticket was written before the rename (D-020). `index.html` already says `Knightbook`, and D-020 keeps the old name only for `.projectspace/` and the skill.

**How it was checked:** Four unit tests in `window-title.test.ts` cover the format, a long name with odd spacing kept verbatim, null, and malformed input. Four renderer tests in `WindowTitle.test.tsx` cover an open project, the welcome screen, a failed open, and a rename picked up by a focus refresh. The built app was run on Windows and reopened this repository. Its title bar read "Projectspace — projectspace", with U+2014 confirmed by char code. The full `pnpm check` passed (lint, format, typecheck, all suites).

**Not verified:** In the real app, only the open-project title was read. Switching, setup, rename, the welcome screen and the loading screens were covered only by renderer tests. The taskbar entry was not inspected separately; Windows takes it from the same window title. A long name next to the window controls was not looked at. Not run on macOS or Linux. The app was not packaged (`pnpm pack:dir`), so the packaging tests ran without a package.

**For you to check:** Open two projects in turn and read the taskbar. Go back to the welcome screen and confirm it says just "Knightbook". Try a long project name and look at the window controls. Say if you'd prefer a different separator, or "— Knightbook" on the end.
