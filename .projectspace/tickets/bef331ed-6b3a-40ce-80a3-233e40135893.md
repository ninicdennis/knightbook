# Documentation section that publishes only listed public guides

## Intended outcome
`/docs/` renders the user guides from repository Markdown with clear navigation, and nothing internal is published by accident.

## Acceptance criteria
- Guides come from one public content folder (for example `apps/website/src/content/docs/`); the build never reads the internal `docs/` specifications, research or proposals. A test fails if a page is generated from outside that folder.
- `/docs/` is an index grouped as Start here, Everyday use, AI setup, and Troubleshooting, and links to each guide route in spec §3.
- Each guide has a sidebar, an on-page contents list, anchored headings, and a readable line length; the sidebar becomes an accessible mobile navigation pattern that works without JavaScript.
- Each guide shows the app version it was written against.
- Relative links between guides are checked at build time, and a broken link fails the build.
- Placeholder guide pages are clearly marked as drafts and are excluded from a production build.

## Notes
Spec §9: one canonical source per guide, and do not publish every file in `docs/`. `docs/using-knightbook.md` is internal but is a useful source when writing the guides themselves (separate tickets). Search is optional at launch.
