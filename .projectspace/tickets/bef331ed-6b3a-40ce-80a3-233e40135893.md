# Documentation section that publishes only listed public guides

## Intended outcome
`/docs/` renders the user guides from repository Markdown with clear navigation, and nothing internal is published by accident.

## Acceptance criteria
- Guides come from one public content folder (for example `apps/website/src/content/docs/`); the build never reads the internal `docs/` specifications, research or proposals. A test fails if a page is generated from outside that folder.
- `/docs/` is an index grouped as Start here, Everyday use, AI setup, and Troubleshooting, and links to each guide route in spec §3.
- Each guide has a sidebar, an on-page contents list, anchored headings, and a readable line length; the sidebar becomes an accessible mobile navigation pattern that works without JavaScript.
- Each guide shows the app version it was written against.
- Relative links between guides are checked at build time, and a broken link fails the build.
- Placeholder guide pages are clearly marked as drafts and are excluded from a production build.

## Notes
Spec §9: one canonical source per guide, and do not publish every file in `docs/`. `docs/using-knightbook.md` is internal but is a useful source when writing the guides themselves (separate tickets). Search is optional at launch.

## Handoff

**What changed.** The work is on branch `feature/website-shell`, with the other website tickets, and is not committed yet. A note is in the technical design ("Documentation"). No dependencies were added: it uses Astro's content collections and bundled zod. No app paths changed.
- **`apps/website/src/content.config.ts`** defines one collection, `docs`: `*.md` from `./src/content/docs` only. Its schema is strict: title, description, group (Start here, Everyday use, AI setup, Troubleshooting), order, `draft`, and `appVersion`, which a non-draft guide must have. Tests can point it at a fixture folder with `KNIGHTBOOK_DOCS_DIR_FOR_TESTS`, passed as a `file://` URL so Windows paths work.
- **`src/content/docs/`** holds six draft placeholders, one per spec §3 route: getting-started, installation, projects-and-documents, tickets-and-verification, connecting-ai, troubleshooting. Each says it has not been written yet and lists what it will cover. Getting started links to Installation, and Connecting an AI tool links to Getting started.
- **`src/docs/guides.ts`:**
  - `publishedGuides()` sorts by group then order, and drops drafts in a production build (`KNIGHTBOOK_SITE_STAGE=production`).
  - The link check resolves every Markdown link under `/docs/` against the guide's own address and stops the build, naming `guide: href (target)` for each link that reaches no published guide.
- **`/docs/`** (`pages/docs/index.astro`) groups the guides, each with a Draft badge where it applies. With none published, it says the guides are being written.
- **`/docs/<name>/`** (`pages/docs/[slug].astro` with `GuideNav.astro`):
  - a 220px sidebar ("Guides" navigation, current guide marked);
  - below 860px, a native `<details>` "Guides" menu instead, with one of the two displayed at a time;
  - the group, the title, then either "Written for Knightbook X" or a draft banner;
  - an "On this page" list of h2 and h3 headings, linking their ids;
  - a 72-character reading column, with headings offset when jumped to.

**How it was checked.**
- `pnpm check` passes. Website: 100 tests, and `astro check` reports 0 errors. Everything else is unchanged. The site builds 11 pages.
- **`docs/docs.test.ts`:**
  - the built `/docs/` pages are exactly the index plus one per file in `src/content/docs`, and `layout.test.ts` pins the whole site's page list the same way;
  - no source file has a relative path, of any depth, resolving into the repository's internal `docs/`, and the index contains no internal text;
  - the index groups are in order, with links to all six spec routes;
  - six Draft badges, and the draft banner on a guide;
  - on a fixture guide with h2, h3 and h2 headings: the sidebar with `aria-current`, the `<details>` Guides menu, the contents links to `#the-four-states`, `#verification` and `#deciding-done` with matching heading ids, and no script;
  - "Written for Knightbook 0.3.0";
  - a published guide without `appVersion` fails the build with the schema message;
  - a link to `../no-such-guide/` fails the build, naming it;
  - in a preview a draft guide is published, while a production build of the same fixture fails because the published guide's link to the dropped draft now leads nowhere, which shows the draft is excluded.
- **Browser:** 1280 light measured: 220px sidebar, 621px article, current guide marked, nothing sideways. 390 dark screenshot: the Guides menu open with all groups, nothing sideways.
- **Verifier:** 3 covered, 3 weakly covered. Gaps closed afterwards: the any-depth internal-docs check, and the missing-`appVersion` build failure.

**Not verified.**
- **No production build has completed.** The homepage's drafts stop every production build, so draft exclusion is shown through the broken link, not by inspecting a finished production output.
- **Layout is browser-only evidence.** The 72-character column and the 860px switch from sidebar to menu have no CI test.
- **No real guide shows a version yet.** All six are drafts; their writing tickets add `appVersion`.
- **Link forms:** only links of the form `../x/` are exercised by tests. `/docs/x/` and `#anchor` forms are handled but untested, and reference-style links (`[a][ref]`) are not checked at all.
- **Search** was not added (optional at launch).
