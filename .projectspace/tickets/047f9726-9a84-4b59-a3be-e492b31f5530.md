# Website tests fail on Windows, blocking every release

## Intended outcome
The release workflow's Windows check passes, so a merge that changes the app publishes its release.

## Acceptance criteria
- The website tests that build the site with Astro pass on a Windows runner, where the repository is on D: and the temp folder on C:.
- The deployment-workflow test passes on a Windows checkout, where Git turns line endings into CRLF.
- Nothing changes on Linux or macOS.

## Notes
Found 2026-10-21: the release runs for #5 (v0.1.2) and #2 (v0.2.0) both stopped at "CI / Check (windows-latest)", so neither was published. Eight build tests failed with `EXDEV: cross-device link not permitted` (Astro renames built assets from `.astro/` into an `--outDir` under `os.tmpdir()`), and `deploy-workflow.test.ts` failed because its regexes expect LF. Pull requests run on Linux only, so this was not seen before merge.

## Handoff (2026-10-21)

**What changed**
- `apps/website/src/test/build-dir.ts`: `buildTempDir(prefix)` makes each test's build folder under `apps/website/node_modules/.cache/knightbook-tests/`, on the same drive as the repository, instead of `os.tmpdir()`. The eight build tests use it.
- `deploy-workflow.test.ts` normalizes CRLF to LF after reading the workflow.
- `.gitattributes` checks out `apps/website/**` and `.github/**` with LF (`text=auto`, so the screenshots stay binary). Renormalizing changed no file.

**How it was checked**
- Linux: the website suite passes (146 passed, 37 skipped, as before); oxlint, Prettier and the website typecheck are clean. The build folders are removed after each run.

**Not verified**
- Windows, until a manual CI run on this branch passes; started with the pull request.
- Other website tests may hide Windows-only failures behind these two; the manual run will show them.

**For you to check**
- The Windows check in the manual CI run. After merge, the release workflow publishes the pending app release.
