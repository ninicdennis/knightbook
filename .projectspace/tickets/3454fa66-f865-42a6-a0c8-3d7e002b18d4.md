# Remember the window between launches

## Intended outcome
The app reopens its window at the size, position and maximized state the user left it in, on a display that is actually attached.

## Acceptance criteria
- Window bounds and maximized state persist in the existing `app-state.json` under Electron's user-data directory. Nothing about the window is written into a project folder.
- The window restores to the stored geometry on launch, and falls back to the current 1280x860 default when there is no stored state, when the values are unusable, or when the restored window would not be visible on any currently attached display.
- `minWidth: 720` and `minHeight: 480` still apply to a restored window, and a stored size smaller than either is raised to it rather than refused.
- Partial, corrupt, or foreign values fall back to the default instead of being carried through, the way `parseSettings` already treats an unrecognised colour scheme.
- Saving is throttled rather than written on every resize and move event, and is also saved when the window closes. A failed write is silent and never interrupts closing or opening: losing this is a convenience regression, which is the stance `writeAppState` already takes.
- A maximized window restores maximized, and keeps the unmaximized bounds it had, so unmaximizing lands somewhere sensible rather than at the default size.

## Notes
Technical design section 3 lists window position alongside checkout paths and recent-project preferences as disposable app state to keep outside the repository. The doc comment on `apps/desktop/src/main/app-state.ts` already claims window state lives there, but nothing reads or writes it, and `createWindow` in `apps/desktop/src/main/index.ts` hardcodes 1280x860 on every launch.

Keep the display-clamping and value-parsing decisions in a pure function that takes the stored value and the available display areas and returns the bounds to use. `parseRememberedEntries` in `remembered-projects.ts` is the shape to follow: the awkward cases are decided in something testable, and the Electron call site stays thin.

`AppState` already merges independent fields, so adding a `window` key alongside `recentProjects` and `settings` must not disturb either.

## Verification
Unit-test the pure function: absent state, a partial object, non-numeric values, a size under the minimums, bounds entirely off every display, bounds partially off one, and a maximized record. Then run the app, move and resize the window, quit, and relaunch. Maximize, quit, relaunch, and unmaximize. Finally hand-edit `app-state.json` to coordinates on a display that is not attached and confirm the window still appears.

## Handoff
**What changed:**
- `src/main/window-placement.ts` (new, pure) parses the stored `{ bounds, maximized }` record and decides the placement. Anything incomplete, non-numeric or non-positive falls back to the default (1280x860, centred by the OS). Sizes below 720x480 are raised. The window counts as visible only if a 32px-high strip of its top edge overlaps some display's work area by at least 100px, so it can still be grabbed. A sliver of border, or a title bar above the screen, falls back to the default.
- `src/main/window-memory.ts` (new) is the Electron glue. It reads the attached displays, saves `getNormalBounds()` plus `isMaximized()` 500ms after the last move, resize, maximize or unmaximize, and saves again on close. A minimized window is not saved, because it reports itself as unmaximized.
- `app-state.ts` has a new `window` key. All four writers (settings, remember, forget, window) now go through one queue, so a frequent window save cannot read the file just before a recent-project change and then write the old list back. `will-quit` waits for that queue to empty; a failed write still lets the app quit.
- `index.ts`: `createWindow` takes the placement, and a maximized window is maximized just before it is shown.

**How it was checked:** Nine new unit tests in `window-placement.test.ts` cover every case in the Verification list above. The desktop typecheck and all 60 main-process tests pass. The built app (`electron-vite build`, then `electron .`) was then run on this Windows machine, which has two displays (2560x1440 at x=-2560, and a 3440x1440 primary), with the window driven through the Win32 API:
1. Moved and resized to (-2300,120) 1000x700 on the left display, closed, relaunched: it reopened at exactly (-2300,120) 1000x700.
2. Maximized, closed, relaunched: it opened maximized. Unmaximizing returned it to (-2300,120) 1000x700.
3. Edited `app-state.json` by hand to x=9000: it opened at 1280x860 centred on the primary, (1080,270).

In every run `recentProjects` and `settings` were left intact, and the app exited cleanly after the close-time save. The user's `app-state.json` was backed up first and restored afterwards.

**Not verified:** The "a failed write never interrupts closing" path was reasoned about, not forced. The queue in `app-state.ts` has no unit test, because that module imports Electron's `app`. Nothing was tested with a DPI scale other than this machine's, with a display unplugged for real (only simulated by coordinates), with fullscreen, or on macOS or Linux. The very first launch was resized by the user's tiling window manager, so the default size was confirmed through the off-screen fallback instead.

**For you to check:** Move and resize the window, quit, relaunch. Maximize, quit, relaunch, unmaximize. If you have a laptop with a detachable monitor, close the app on the external display, unplug it, and relaunch.
