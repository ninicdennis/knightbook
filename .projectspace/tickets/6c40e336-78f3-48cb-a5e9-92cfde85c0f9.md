# Add a verifier agent, guard hooks, and a handoff skill for Claude Code

## Intended outcome
Claude Code sessions in this repository catch the failures the board keeps recording before handoff: tests that do not exercise their own case, files drifting past the size limit, hand edits to `.projectspace/`, and layout checks that get skipped.

## Acceptance criteria
- `.claude/agents/verifier.md` defines a subagent with no write access to source or the board. Given a ticket id, it reads the acceptance criteria, finds the test that covers each one, checks that the test's data actually triggers the case, and reports each criterion as covered, weakly covered, or uncovered, with evidence.
- A hook in `.claude/settings.json` reports a file edited or written by the agent when it passes 300 lines, and flags it more strongly at 400, naming the file and its line count.
- A hook blocks agent Edit and Write calls to any path under `.projectspace/`, saying that board changes go through the `knightbook` MCP tools. MCP tool writes are unaffected.
- `.claude/skills/handoff/SKILL.md` gives the end-of-ticket steps: `pnpm check`, `pnpm build:mcp` when `packages/mcp` changed, `pnpm preview:board` checked at a narrow and a wide width against `docs/research/ui-ux-design-direction.md` when the renderer changed, running the verifier, and writing the handoff note as What changed / How it was checked / Not verified / For you to check.
- The hooks work under Git Bash on Windows and do not assume a Unix-only tool, since CI and contributors also run Linux and macOS.
- Each hook script is shown to give the right result when fed the input Claude Code sends it: one file over the limit, one attempted `.projectspace/` edit, with the output recorded in the handoff. Seeing them fire in a live session is not required (changed 2026-09-26, see Notes).
- AGENTS.md mentions the verifier and handoff skill in a line or two, and nothing in it is duplicated into the skill.
- `.claude/` is committed. `.claude/launch.json` is no longer excluded in `.git/info/exclude`.

## Notes
Came out of a review of the board's history on 2026-09-24. The evidence behind each piece:

- **Verifier:** the backlog reorder ticket was sent back because the test "keeps entries the caller did not mention" used a manifest with no duplicates, so it never hit the bug it was named for. A reviewer with fresh context, checking criterion against test data, is aimed at that.
- **Size hook:** four tickets were after-the-fact cleanup for the 400-line limit (App.tsx, the MCP ticket tools, four files just over, and the preview typecheck that fell behind). A hook that fires at edit time is cheaper than a ticket later.
- **`.projectspace/` hook:** AGENTS.md already forbids hand edits; the hook makes the rule mechanical.
- **Handoff skill:** handoffs repeatedly say the change was not seen in a real window, and the cramped action bar was found by the user. The checklist exists in CLAUDE.md prose; a skill makes the layout pass an explicit step.

Out of scope: plugin connectors (Knightbook is the tracker), more than one agent, and multi-agent workflows. The global copy of the workflow skill at `~/.claude/skills/projectspace/` is outside the repository and is not changed here; it matches `skills/projectspace/SKILL.md` today, but only the repo copy is covered by `guidance.test.ts`.

Keep hook scripts small and in the repository (for example under `.claude/hooks/`), run by Node since the project already requires it.

## Handoff
**What changed:** Branch `feature/claude-code-verifier-and-hooks`, uncommitted.
- `.claude/settings.json` wires two Node hooks. They are run as `node "$CLAUDE_PROJECT_DIR/.claude/hooks/…"`, with no Unix-only tools; the scripts use only `node:fs` and `node:path`.
- `.claude/hooks/guard-projectspace.mjs` is a PreToolUse hook on Edit, MultiEdit, Write and NotebookEdit. It exits 2 with a message pointing at the knightbook MCP tools when the target's first path segment under the project is `.projectspace`. It ignores case on Windows and macOS, whose file systems do, and respects case on Linux. MCP tool calls never reach it.
- `.claude/hooks/file-size.mjs` is a PostToolUse hook on Edit, MultiEdit and Write, and counts code files only (`.ts .tsx .mts .cts .js .jsx .mjs .cjs .css`). It skips `node_modules`, `dist`, `out`, `release` and `coverage`. Past 300 lines it adds context naming the file and its line count. At 400 or more it returns `decision: block` with the same details: Claude Code shows that to the agent as something to act on, and the edit itself is not undone. Prose is exempt on purpose, because the spec is long by design.
- `.claude/agents/verifier.md`: tools are Read, Grep, Glob and three read-only knightbook tools (ticket_read, document_read, project_search). It has no Bash, so it cannot write. Per criterion it checks whether the test's data contains the condition, whether the assertion would fail without the behaviour, and whether it asserts the real outcome or a proxy. Verdicts are covered, weakly covered, uncovered, or "not a code criterion", each citing file and line.
- `.claude/skills/handoff/SKILL.md` has six steps: `pnpm check` (a skip is not a pass); `build:mcp` when `packages/mcp` or `packages/core` changed, since core is bundled into it; a layout pass at about 800 and 1600px in both schemes against the design-direction doc, using the `board-preview` launch configuration; the verifier; the four-heading note; then Verification. It points to AGENTS.md and the projectspace skill rather than repeating them.
- AGENTS.md: two bullets under "This project's own board".
- `.git/info/exclude`: removed `.claude/launch.json` and a bare `launch.json` line. That file is local to this clone, so it is not part of the diff.
