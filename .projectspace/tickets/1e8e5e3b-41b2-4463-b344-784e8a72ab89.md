# Set up the Astro website package with layout and design tokens

## Intended outcome
An `apps/website` workspace package builds a static Astro site with a shared layout, so every later page ticket only adds content.

## Acceptance criteria
- `apps/website` builds to static output with `pnpm --filter @knightbook/website build`, and a local dev/preview command is documented in the README command table.
- Its lint, format, typecheck and tests run as part of `pnpm check`, and CI runs its build.
- A base layout has the header (Knightbook wordmark and logo, How it works, Documentation, Releases, Download), a footer with space for license and support links, and a skip link.
- The mobile header keeps a visible Download action and accessible navigation that works without JavaScript.
- A small token set (background, surface, text, muted, accent, success, warning, danger, border, radius, spacing) in light and dark follows the desktop app's muted blue accent and system typography.
- A useful 404 page exists.
- The pages ship no client-side JavaScript by default.
- Choosing Astro is recorded as a numbered, dated decision in the technical design.

## Notes
The user chose Astro on 2026-09-29: static output, Markdown guides, no JS by default, which fits the no-JS download requirement (spec §8). Follow the feature-folder convention (D-027). Use `docs/assets/knightbook-logo.png` as the only logo source. No analytics or tracking scripts (spec §9).
