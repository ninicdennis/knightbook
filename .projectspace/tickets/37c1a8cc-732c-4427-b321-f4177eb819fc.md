# Split App.tsx, which is close to the size limit

## Intended outcome
`apps/desktop/src/renderer/App.tsx` is well under the 400-line hard limit, and reads as the window's wiring rather than holding navigation and refresh logic itself.

## Acceptance criteria
- `App.tsx` is under 250 lines.
- Refresh and in-app navigation (which view, which ticket, document or plan is open) live in hooks in `renderer/app/`; the board-level dialogs are rendered by their own component.
- No behaviour change: `pnpm check` passes without editing any existing test.

## Notes
Found while splitting the contract (0b9b5e5f): App.tsx was at 380 lines. It declares no types of its own, so the size is state and JSX wiring, not type declarations.

## Handoff
**What changed:** On branch `feature/file-organization`, uncommitted, in the same working tree as the contract split (0b9b5e5f). `App.tsx` went from 380 to 240 lines. Four files were added in `renderer/app/`:
- `useProjectRefresh.ts`: manual refresh, refresh on focus, and the refresh token.
- `useProjectNavigation.ts`: which view is showing, and which ticket, document or plan is open; it also closes a ticket that vanished and resets navigation on a project switch.
- `ProjectDialogs.tsx`: the archive-column, new-ticket, completion and verification-issue dialogs.
- `ProjectViewSwitch.tsx`: Board, Documents, Plans or Archive.

The code inside them is moved unchanged. With those four files `app/` would have held 22 files, over the D-027 threshold. So the files for choosing and opening a project (`Welcome`, `SetupFolder`, `ProjectSwitcher`, `ProjectStatusScreens`, `useProjectScreen`, `screen.ts` and their two tests) moved with `git mv` to a new `renderer/projects/` folder, and D-027 lists it.
**How it was checked:** `pnpm check` exits 0, with the same test-file counts (desktop 53). The only edits to existing tests are import paths in the two tests that moved to `projects/`. In `pnpm preview:board`, I switched between Board, Documents, Plans and Archive, opened a ticket and closed it with Escape, and opened search from the header button and Ctrl+K. There were no console errors.
**Not verified:** In the preview pane, search results never appeared after typing, because the pane was not visible and the browser held back its timers. An unchanged copy of the last commit behaved the same in that pane, so this is not caused by this change; the renderer's search tests pass. The packaged app was not rebuilt.
**For you to check:** Use the app normally: switch views, open a ticket from the board and from a search result, follow a link from a document to a ticket and back, and refresh.
