# Filter the whole board by plan

## Intended outcome
Use one plan selector across all four board columns so separate efforts, such as the website and desktop app, remain easy to follow in the same repository.

## Acceptance criteria
- A visible selector labelled "Plan" above the board offers All tickets, each existing plan, and No plan. All tickets is the initial default.
- Selecting one plan shows the active tickets linked anywhere in its phases, once per ticket. Shared tickets appear under each plan that links them. No plan shows tickets with no plan membership.
- The selection applies to Backlog, In progress, Verification, and Done together. Column counts reflect matching tickets; a board summary shows matching versus total active tickets and provides an easy reset to All tickets.
- The selection is remembered per project across navigation and reopening the app, without leaking between checkouts. If the selected plan no longer exists, fall back to All tickets.
- Each plan offers View on board, which opens the board with that plan selected. An empty plan shows a clear empty filtered view and a way to reset.
- Filtering preserves ticket status, backlog order, plan membership, dependency evaluation, and access to prerequisites outside the selected plan. Archived tickets remain outside the working board.
- Header search, Documents, the Plans list, and MCP access remain project-wide. The selected view does not implicitly scope AI work or change ticket_next.

## Notes
Use the existing plan-to-ticket relationships; no new tags, separate boards, multi-select, or active-plan workflow state. This complements the existing per-column type/state filtering ticket rather than replacing it. If both filters exist, their conditions should combine.

Record the agreed view behavior in the specification and technical design during implementation, including a numbered, dated decision with its reasoning. Verify with multiple plans, a shared ticket, an unassigned ticket, an empty plan, and a dependency outside the selected plan.

## Handoff
**What changed:**
- Host: `buildView` adds `plans: { id, title, ticketIds }[]` to `ProjectView`, from the same plan files the Plans view reads, each ticket once across phases.
- Renderer:
  - `board/usePlanFilter.ts` keeps the choice (All tickets, a plan, or No plan) in the window's own storage keyed by checkout path, the same approach as collapsed document folders. It falls back to All tickets when the remembered plan is gone.
  - `board/PlanFilterBar.tsx` is the "Plan" selector, plus a summary ("Showing 2 of 14 active tickets in MVP.", "No active tickets in X.", or "with no plan") and a "Show all tickets" button.
  - `Board.tsx` filters every column. Counts are of matching cards, and a column whose cards are all hidden says "N tickets here are hidden by the plan filter" rather than looking empty.
  - "Archive all in this column" is offered only on the unfiltered board, because it would otherwise archive hidden cards. This was not in the ticket; it is my addition.
  - Each plan's detail has "View on board", which remembers the plan and opens the board.
- Docs: D-035 in the spec; the technical design layout note mentions it.
- Nothing else reads the filter: search, Documents, Plans, next up, dependency readiness, reordering and MCP are unchanged.

**How it was checked:**
- `pnpm check` passes.
- Host `project-view.test.ts` (2, real plan files): a ticket in two phases is listed once, an empty plan has no tickets, and no plans gives `[]`.
- `PlanFilter.test.tsx` (14), against Website and Desktop app plans sharing one ticket, an empty plan, tickets in no plan, and a prerequisite outside the plan:
  - the default and the option list;
  - one plan across columns, with the shared ticket under both plans;
  - counts per column including Verification and In progress;
  - the hidden-cards message;
  - an archived ticket that a plan links is neither shown nor counted;
  - No plan;
  - an empty plan and its reset;
  - "Waiting on 1" still counts the hidden prerequisite;
  - Next up is shown unfiltered and not re-picked under a plan;
  - column archive is hidden while filtered;
  - choosing writes nothing and reads the project once;
  - the choice is remembered across remounting, is not carried to another checkout of the same project, and falls back when the plan is gone;
  - View on board from the Plans view.
- Board preview (stub data) at 1600 px dark and 800 px light: filtered to MVP, the choice was kept across a page reload, and the empty plan read clearly.
- Verifier: 3 covered, 4 weakly covered. Its gaps were then closed for Verification and In progress counts, archived tickets, the next-up positive control, and a real between-checkouts test.
