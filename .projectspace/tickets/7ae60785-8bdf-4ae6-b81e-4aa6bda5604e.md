# Copy the MCP configuration in the format of Claude, Codex, or OpenCode

## Intended outcome
The user picks their AI client and gets a snippet they can paste straight into that client's config file, with nothing to reshape by hand.

## Problem
`CopyMcpConfig.tsx` copies one inner object, `{ command, args }`. That is the Claude shape without its `mcpServers.knightbook` wrapper, and it does not work in other clients. OpenCode wants `mcp.knightbook` with `type: "local"` and a single `command` array (program followed by its arguments). Codex wants TOML. The launch command is the same for all three; only the wrapping differs. Found on 2026-09-24 while connecting OpenCode by hand.

## Acceptance criteria
- Replace the single copy control with a choice of client: Claude, Codex, OpenCode. Keep the compact footer icon usable.
- Each option copies a complete snippet, outer key included, so it can be pasted without wrapping:
  - Claude (Claude Code, Claude Desktop): JSON `{ "mcpServers": { "knightbook": { "command", "args" } } }`. Consider also offering the `claude mcp add knightbook -- ...` command line.
  - Codex: TOML `[mcp_servers.knightbook]` with `command` and `args`.
  - OpenCode: JSON `{ "mcp": { "knightbook": { "type": "local", "command": [...], "enabled": true } } }`.
- Say where the snippet goes for each client (which file, and whether an existing server list should be merged rather than duplicated).
- Build the snippets in one pure function in `apps/desktop/src/shared` from the existing `McpLaunchCommand`. No new contract operation; the renderer already has everything it needs.
- Unit tests for each format, including Windows paths (backslashes escaped in JSON, TOML strings that need no escaping) and paths containing spaces.
- Check each format against the client's current documentation during implementation and record the checked date and source in the technical design as a numbered decision. The formats above are from memory and are unverified.

## Notes
- Clients other than these three still need a fallback. The generic `command` and `args` values are enough for most of them.
- These formats belong to the clients and can change without notice. Keeping the list to three limits that exposure.
- Overlaps with 9f4177e9 (Bundle the workflow skill and add guided AI setup), which calls for client-specific connection instructions as part of a larger onboarding flow. This ticket is the smaller, standalone slice: correct per-client snippets from the existing copy control. 9f4177e9 can build on it.
