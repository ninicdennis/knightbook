# Project switcher

## Intended outcome
A hamburger menu opens a side navigation for moving between projects, replacing the header folder button as the way to change project.

## Acceptance criteria
- The header hamburger opens a side navigation listing remembered projects with name and path; the current one is highlighted.
- Choosing one switches to it. An Open folder item sits at the bottom.
- Removing an entry forgets it only. Nothing on disk is touched.
- A remembered path that no longer exists is shown as unavailable with the reason, not silently dropped.
- Names are remembered as local app state alongside the path; today only paths are stored. None of it is project content or travels through Git (design section 3).
- Keyboard operable and usable at narrow widths.
- Switching while a move is in flight either waits or is refused with a message.

## Notes
Running MCP connections are bound to their own root and are unaffected by which project the window shows (design section 4). The interface copy should say so.

## Implementation notes (for your verification)
Built and moved to Verification by the AI. Only you decide Done.

- Header hamburger opens a left drawer. It lists remembered projects (name, path), marks the open one, and has Open folder at the bottom. The old header folder button is gone.
- Each entry is checked when the drawer opens. A missing folder, a non-folder, or a folder with no project records shows as Unavailable with the reason and cannot be opened, but can be forgotten.
- Forget removes the entry from this machine's app state only. It is not offered for the project that is open.
- Names are now stored alongside paths in app-state.json. Old entries that were bare paths still load; their name falls back to the folder name until the project is next opened.
- While a ticket move is in flight the drawer says so and disables switching and Open folder.
- The drawer says connected AI tools keep using their own project.
- Switching returns to the Board and closes any ticket dialog.

## Not verified
- The packaged window itself was not screenshotted; verified by tests (14 renderer, 7 main-process), a real Chromium view of the drawer at wide and 375px widths, and a clean launch of the packaged build.
- Light mode, and long paths or long project names.
- Keyboard: relies on Mantine's drawer focus handling (Tab, Escape); not exercised by hand.
- Moving a project that is remembered but unavailable back into place is not offered; use Open folder.
- The header hamburger only exists while a project is open. On the welcome and failed screens the existing recent list and Open a folder buttons are used.
