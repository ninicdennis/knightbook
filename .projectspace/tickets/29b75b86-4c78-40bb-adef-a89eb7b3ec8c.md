# A ticket's id is readable and copyable

## Intended outcome
The ticket's id can be read and copied from its detail dialog, so it can be named to an AI client or pasted into another ticket's `depends_on`.

## Acceptance criteria
- The open ticket shows its id, and a copy control puts the full id on the clipboard. What is copied is always the whole id, even if what is shown is shortened.
- Copying confirms it happened, and says so if it did not. `CopyMcpConfig.tsx` already does this with Mantine's `CopyButton` and is the pattern to follow.
- The id is the quietest thing in the header. The title stays the strongest, and status, type and review keep the hierarchy they have.
- The copy control is reachable by keyboard and has an accessible name that says what it copies. An icon alone is not enough.
- Nothing about the id is editable, and no new host operation is needed.

## Notes
Ids are how tickets are referred to everywhere outside the board: `depends_on` holds them, the MCP tools take them, and a request to an AI client has to name one. Right now an id is only visible in the app when a dependency is broken, inside the error text in `TicketDetailSections.tsx`, and otherwise has to be read off a filename in `.projectspace/tickets/`.

Technical design section 3 allows the interface to abbreviate an id when that is unambiguous. A short form is easier to read aloud and to match against a filename; a full id is what other tools need. Decide which is shown, keep the copy faithful to the whole thing, and write down the reason.

## Verification
Open a ticket, copy the id, and paste it somewhere: it matches the filename under `.projectspace/tickets/` and the `id` in that file's frontmatter. Reach the control by keyboard and confirm what a screen reader would announce. Check the header still reads title first in both colour schemes and in a narrow window.
