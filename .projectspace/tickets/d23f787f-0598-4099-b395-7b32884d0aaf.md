# A coherent, responsive application shell

## Intended outcome
The board, project header, search, and connection footer feel like one application, with a readable project identity and controls that fit smaller windows.

## Acceptance criteria
- Apply shared surface roles from surfaces.css to the app-owned header/footer and controls; preserve the existing board palette and quiet Done treatment.
- Align project identity, centered search where space allows, view navigation, Refresh, and Settings with consistent heights and spacing. Give selected navigation and keyboard focus clear treatments without competing with Next up.
- Long names and checkout paths cannot squeeze search or utility controls offscreen. Keep the full checkout available accessibly; use a deliberate narrow-width reflow and account for the resulting header height in the main layout.
- Keep Ctrl/Cmd+K behavior, search scope, loading states, tooltips, navigation, and MCP status behavior intact. Keep the footer subordinate but legible.
- Reconcile the current light native-window background (#f4f5f7 in window-theme.ts) with the renderer window token (#eef0f4) to avoid a mismatch during resize/startup. Follow the selected light/dark/system scheme without replacing native title/menu controls.
- Reserve space for future Archive navigation through flexible layout, without adding an Archive control in this ticket.

App.tsx, components/ProjectHeader.tsx, components/McpStatusFooter.tsx, surfaces.css, theme.ts, and main/window-theme.ts. Existing search ticket: `4ec743fa-902e-4906-8cc2-4cb0a72ae126`.

## Handoff
**What changed:** (branch `feature/unified-app-shell`, uncommitted)
- New `renderer/shell.css`. The header and footer sit on the window layer (`--ps-app-bg`) with a hairline edge, and the header controls use the card layer. View navigation sits on the column layer, and the selected view is raised onto the card layer and set in semibold. The accent is left for Next up and focus rings.
- The header is now a grid: identity on the left, search centred (up to 22.5rem), navigation and utilities on the right. Every control is 34px high. Below Mantine's `md` breakpoint (992px) it reflows onto two rows: identity with Refresh/Settings, then navigation with search taking the rest. `App.tsx` gives AppShell the matching height (`{ base: 104, md: 60 }`, was a fixed 72).
- The name and path stay on one line each and truncate. The path truncates from the start, because the end is what tells clones apart. The full text stays in the DOM and in a hover tooltip. The project name is now an `h1` (was an `h3`).
- New `--ps-text-muted` token in surfaces.css, used for the path, unselected views, search text and the footer's secondary text. Mantine's `dimmed` measured about 2.5:1 on the light column layer.
- The native light window background is now `#eef0f4` (was `#f4f5f7`). `WINDOW_BACKGROUND` is exported, and `window-theme.test.ts` fails if it drifts from surfaces.css.
- The Archive tab already existed before this ticket, so nothing new was added for it. The flexible actions column keeps room for more navigation.

**How it was checked:**
- `pnpm check` passes: lint, format, typecheck, all suites (desktop 270 passed, 1 skipped). New tests: `Header.test.tsx` (h1 name, full path in the DOM, every header control reachable) and `window-theme.test.ts`.
- In `pnpm preview:board`, at 1280×860 and 900×650, dark and light, with an injected long name and path:
  - No horizontal scroll.
  - At 900 the header content measured 83px inside the 104px header, and the board starts below it.
  - At 450px wide (a 900px window at 200% zoom, run in a same-origin iframe) all controls end inside the window.
- Tab order is menu → search → views → Refresh → Settings. Each shows the 2px accent focus ring.
- Measured contrast with transitions turned off (lowest first): light unselected view 4.62, dark search text 4.71, light footer 5.06, dark footer 5.86.
- The Documents view still fits 900×650 with no page scroll.

**Not verified:**
- Not run in the Electron window, and not packaged. The native background change (startup/resize band) and native title/menu behaviour were not observed.
- Real browser zoom was not tested. 200% was simulated by width only.
- Ctrl/Cmd+K and search scope were not re-run by hand. Their existing tests still pass, and the code paths are unchanged.
- macOS/Linux were not checked.

- Watch startup in light mode for any edge band.
- Decide whether semibold plus a raised surface is enough selected-view emphasis for you.
