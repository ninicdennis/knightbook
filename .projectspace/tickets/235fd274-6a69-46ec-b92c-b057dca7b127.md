# Include documents picked in the app's file dialog

## Intended outcome
Choosing a file or folder with "Include" in the Documents view adds it to the project, on Windows as on other platforms, instead of failing with "Path must be project-relative: C:\Users\...\docs".

## Acceptance criteria
- A file and a folder inside the project, picked by their absolute path, are stored in the manifest as forward-slash project-relative paths (`docs`, `README.md`).
- A picked path whose letter case differs from the root's on Windows is still recognised as inside the project.
- A picked path beside the project (`car-meet-app-old`), on another drive, or above the root is refused with `outside_project`, and nothing is stored.
- The MCP `documents_include` tool still accepts only project-relative paths.

## Notes
Found by Denny on Windows, 2026-10-21, including `docs` in his car-meet-app project. The picker returned absolute paths and `pickAndInclude` passed them to `includeDocuments`, which only takes project-relative ones, so it failed on every platform. Fixed in PR #12 (merged as 2807fe6).

## Handoff
**What changed:** `relativeToRoot` and `projectRelativeFromAbsolute` in `packages/core/src/records/paths.ts` make an absolute path project-relative (after resolving symlinks) and refuse one outside the root. `includePickedPaths` in `packages/core/src/documents/documents.ts` uses them before `includeDocuments`, and the desktop picker handler (`apps/desktop/src/main/documents/documents-ipc.ts`) calls it. `includeDocuments` and the MCP tool are unchanged.
**How it was checked:** `paths.test.ts` runs Windows rules (`path.win32`) on `C:\Users\Denny\Projects\car-meet-app\docs`: folder, nested file, different case, a `..notes` folder, and refusal of a sibling folder, a `D:` path and the parent. `documents.test.ts` includes a real folder and file by absolute path and refuses one outside the project without storing anything. All fail without the fix. `pnpm check` passed and CI on Linux was green on PR #12.
**Not verified:** The app was not run, and nothing was tried on Windows or macOS; the Windows cases are tested with Node's `path.win32` on Linux, not on a real Windows filesystem.
**For you to check:** On Windows, after the next release, include a folder and a single Markdown file through the Documents view's picker and confirm they appear in the list. Picking something outside the project should show an error and add nothing.
