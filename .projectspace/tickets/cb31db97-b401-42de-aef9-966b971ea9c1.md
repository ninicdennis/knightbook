# Replace the default title bar with a header that matches Knightbook

## Intended outcome
Replace the default operating-system title strip with a custom title bar that fits Knightbook's visual design, while keeping familiar window controls and behavior. The user finds the current Windows title bar unattractive.

## Acceptance criteria
- Present a concise design direction before implementation. Consider integrating the title bar with the existing app header to reduce stacked bars; the exact layout remains to be settled.
- Match the app's light, dark and system theme settings, with readable text and controls in active and inactive windows.
- Show Knightbook branding using the existing approved PNG artwork and preserve the current project/window-title information, including its use by the operating system.
- Retain native minimize, maximize/restore and close controls where supported, with platform-appropriate placement and reserved space so app actions cannot overlap them.
- Provide a draggable region while keeping buttons, inputs, menus and other interactive content clickable and keyboard accessible.
- Verify dragging, resizing, double-click maximize/restore, Windows snapping, minimize, close, fullscreen behavior and remembered window placement. Test narrow windows and display scaling.
- Verify the title bar on the welcome/project-selection screens as well as an open project. Preserve existing header actions and keyboard shortcuts.
- Define platform-specific behavior and record the decision in the technical design. Report actual Windows/macOS/Linux verification separately; do not infer cross-platform behavior from a Windows run.
- Run pnpm check and validate the title bar in the packaged desktop app; a browser preview alone cannot verify native window behavior.

## Notes
The recommended starting point is Electron's titleBarStyle: 'hidden' with titleBarOverlay, retaining platform window controls while styling the surrounding header. This recommendation does not require an additional title-bar library or fully custom window-control buttons.

See [Electron window options](https://www.electronjs.org/docs/latest/api/structures/base-window-options) and the existing [UI design direction](../../docs/research/ui-ux-design-direction.md). Confirm current Electron behavior when implementing.

Keep the change focused on the title bar and necessary header integration; do not redesign unrelated screens. Ticket creation does not start implementation.

## Handoff
**What changed:** Branch `feature/header-and-title-bar`, uncommitted, built on top of `3d28db74`, which must land first. The user approved the design in chat on 2026-09-25: the header's first row is the title bar.
- `src/main/window/title-bar.ts` sets `titleBarStyle: 'hidden'` and `titleBarOverlay` (48px, the app's background and text colours). It repaints the controls on theme change and dims them on blur. On macOS the traffic lights are placed in the middle of the row, with `titleBarOverlay: true` for the safe-area variables.
- In the renderer, the first header row is a drag region. Buttons, links and inputs opt out, and the row keeps clear of the controls using `env(titlebar-area-*)` (`app/shell.css`).
- The Knightbook mark sits before the project name (`app/TitleBar.tsx`). The welcome, setup, loading and error screens get a 48px strip with the mark and "Knightbook".
- The mark is a 96px PNG. `derive:icon` now also writes it; `build/icon.png` came out byte-identical.
- Drawers now open below the title bar and dialogs keep at least 56px from the top. The Settings drawer's close button had landed under the native close button, and Electron's drag regions ignore anything layered over them.
- The first row switched from grid to flex, so search shrinks before the project name truncates. A -4px margin that clipped the name was removed.
- Decision D-030 in the spec. Per-platform table in technical design section 1, "Custom title bar".

**How it was checked:** `pnpm check` passes (desktop 429 tests, 1 skipped). The new `title-bar.test.ts` fails if the overlay colours or height drift from the stylesheets. The packaged app was built with `electron-builder --dir` into a scratch folder, because the user's copy in `release/` was open; `pnpm pack:dir` refused to overwrite it. Run on Windows 10 at 100% scaling, with GlazeWM stopped:
- Hit-test (`WM_NCHITTEST`): empty row space is CAPTION; project name, search and Settings are CLIENT; the three buttons are MIN/MAX/CLOSE; the upper edge is TOP.
- Buttons: maximize, restore and minimize via the buttons all work. Clicking the close button quits the app.
- Double-click on empty space maximizes and restores.
- Dragging: the user confirmed it works with a real mouse. Synthetic drags from the automation tool did not move the window.
- Colours: control symbols measure `#c9cdd6` focused and `#8c939f` unfocused (dark). Switching to Light repainted them dark-on-light.
- Settings opens from inside the drag row.
- At the minimum width (720px) search folds to an icon and nothing overlaps the controls.
- The loading-screen strip shows the mark, "Knightbook" and the controls.

**Not verified:**

- Display scaling other than 100%.
- Fullscreen: the app offers no fullscreen command on Windows, and macOS fullscreen was not tried.
- Remembered placement after a maximize-then-quit.
- Keyboard focus order across the new row.
- The welcome and setup screens were not opened (only loading was seen).
- The mark at small size, which the user said they will judge.
- macOS and Linux: not launched; see the technical design table.
- `pnpm pack:dir` into `release/` was not run.
