# Check the full visitor journey against the launch criteria, then publish the site

## Intended outcome
There is recorded evidence for each spec §10 launch criterion, and the site is live on the production domain with real release data.

## Acceptance criteria
- The release-data file holds the real public release for Windows x64, macOS arm64 and x64, and Linux x64 deb.
- Each enabled download is fetched from the production site without a login, and its version, architecture, size and checksum match the asset.
- One person who was not involved reads only the homepage and explains what Knightbook is and what the external AI does versus the app. Their answer is recorded.
- The getting-started guide and one client guide are followed from the production site on a clean machine, including reading the project with the desktop window closed and an example handoff that keeps the user's completion decision separate from review.
- A link check over the production site finds no broken internal links or asset links; the accessibility and no-JS tests pass against production.
- A search of the built output finds no draft markers, placeholders, private paths or internal specification pages.
- License, pricing, support, privacy, known issues and manual update instructions are all present and match the distributed product.
- The site is published, and the rollback procedure is confirmed to work from the live state.
- Each criterion's evidence is recorded on this ticket.

## Notes
Spec §10: publish only after the release assets are public. All three platforms are launch targets (user, 2026-09-29). The user decides when to go live and whether this is Done.
