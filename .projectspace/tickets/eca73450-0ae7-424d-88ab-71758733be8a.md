# Package and check the Intel Mac app in CI

## Intended outcome
A CI run on macOS packages both the arm64 and the x64 app and runs `packaged-architecture.test.ts` against each, so a runtime staged for the wrong CPU fails before a release rather than after.

## Acceptance criteria
- It is established, from a real macOS CI run, whether `pnpm pack:dir` (`electron-builder --dir`) packages both mac architectures or only the runner's own, and the packaging findings say which.
- If only one: the macOS package job packages both (for example `--mac --arm64 --x64`), within the Actions allowance the user accepts (D-031), or the user decides the release build is where x64 is first checked.
- Under `REQUIRE_PACKAGED_APP` on macOS, the packaged suite fails when either architecture's package is missing, so it cannot pass on half the release.
- Whether the x64 server was started under Rosetta on the arm runner is stated.
