# Refresh on file changes

## Intended outcome
The window reflects changes made through MCP, an external editor, or a git pull without reopening the project.

## Acceptance criteria
- Watch only the reserved folder and included documents; coalesce bursts; close watchers when a project closes (design section 2).
- Events trigger a re-read; revision checks stay the source of truth.
- Unsaved state is never lost to a refresh.

## Notes
Found while building this project through MCP: the app reads once on open, so tickets an AI creates appear only after reopening. The spec's Git portability section expects a refresh after pull or branch switch.

## Interim behavior already shipped
A Refresh button and a refresh when the window regains focus were added while building the ticket detail view. Together they cover the common case, an AI tool writing while the user is elsewhere. This ticket remains for live updates while the window is in front, and for included documents changing underneath an open document.
