# Create a fictional sample project and capture release screenshots

## Intended outcome
The homepage and guides use real screenshots of the released app showing a small, understandable, fictional project, with nothing private in them.

## Acceptance criteria
- A small fictional sample project is checked into the website package (for example a recipe app or a garden planner), with a few documents and tickets across all four columns, including one in Verification with a handoff note.
- Screenshots are captured from the installed release build, not the development app: the board as the main image, a document with its review state, and the steps the getting-started guide needs.
- No screenshot shows a personal path, username, client name, secret or real project content.
- Every screenshot has alt text that explains what it shows, and no instruction depends on the image alone.
- Images are compressed and sized for the web, with light and dark captures if the site offers both.
- The capture steps are written down so screenshots can be retaken when labels or the workflow change.

## Notes
Spec §4 "Show the product" and §6: do not show proposed features (such as the formatted editor) as released screens. Recheck onboarding labels against the release used.
