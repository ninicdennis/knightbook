# Create a document through MCP

## Intended outcome
An AI tool can add a new project document without needing separate filesystem access.

## Acceptance criteria
- A tool creates a new Markdown document at a project-relative path and registers it, refusing to overwrite an existing file.
- It works for a nested path the user invented, creating intermediate folders.
- The specification's "document from an optional template" is either provided or explicitly dropped, with the decision recorded in the project's documents.
- The workflow skill's "What you cannot do through MCP today" section is updated to match.

## Notes
Found running the specification validation scenario (ticket 2e4a254f), steps 1 and 14.

`document_write` edits an existing document and cannot create one, and `documents_include` only registers a file that is already there. Both scenario steps were completed by writing the file with a separate file tool and then including it, which works but assumes the AI client has filesystem access to the project. A client with only this MCP server cannot capture an idea or a specification as a document at all, which is step 1 of the scenario.

Nothing here is broken; this is a missing capability the scenario expects. No template mechanism exists either, so the "create a document from an optional template and freely change its structure" half of step 14 has nothing to exercise.

## Handoff
**What changed:** New core `createDocument(project, path, content)` in `packages/core/src/documents.ts`. It accepts only `.md` paths (new error code `invalid_path`) and applies the same boundary rules as inclusion (no escaping the project, nothing in `.projectspace/`). It writes through `writeRecord` with `mustNotExist`, so the existence check and the write happen under the write lock and it never overwrites. Missing folders are created. It then includes the file, unless an already-included folder covers it, in which case no second entry is added. New MCP tool `document_create` returns `path`, `revision` and `included_via`. Templates were dropped for MCP and recorded as D-023 in `docs/project-workspace-spec.md`: the AI writes the whole content anyway, and a starting shape belongs to the in-app ticket `6f8476ef`. The skill's Documents section and "What you cannot do" section are updated. The technical design's MCP table lists the tool.
**How it was checked:** `packages/core/src/document-create.test.ts` covers exact content and inclusion (re-read from disk), a nested invented path, a file under an included folder getting no extra entry, refusing to overwrite with bytes and manifest untouched, a non-`.md` path, and paths outside the project or in `.projectspace/`. `packages/mcp/src/document-create.test.ts` runs create → `documents_list` → `document_write` with the returned revision, plus `already_exists` on a second create. `guidance.test.ts` confirms the skill names the new tool. `pnpm check` passed.
**Not verified:** Calling `document_create` from a live AI client. This session's MCP connection started before the rebuild, so it still runs the old server. `packages/mcp/dist/server.mjs` has been rebuilt; clients need to reconnect to see the tool.
**For you to check:** After reconnecting an AI client, ask it to create `notes/some-idea.md`. Check it appears under Documents and that asking again for the same path is refused.
