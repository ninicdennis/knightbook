# Run checks and build on every pull request

## Intended outcome
Every pull request runs the linter, formatting check, typecheck, tests and a real build of the app automatically, so a change that breaks any of them is visible before it is merged.

## Acceptance criteria
- A GitHub Actions workflow runs on every pull request to main and on every push to main.
- It installs with the frozen lockfile, the pinned pnpm and Node 24, and fails on any failure in lint, formatting, typecheck or tests (the same as pnpm check).
- It builds the MCP bundle and the desktop app, packages the unpacked app, and runs the packaged-app tests. Those tests must not be silently skipped in CI.
- It runs on Windows, the platform validated so far. Whether Linux and macOS are included, and whether their failures block, is decided from what a first run shows.
- Read-only repository permissions, no secrets, and no publishing. External actions are pinned to reviewed commit SHAs. A newer run on the same pull request cancels the older one.
- The README says what runs and how to run the same checks locally. Requiring the workflow before merging is a GitHub branch-protection setting the owner turns on; it is not something the workflow can do.

## Notes
This is pull-request validation only. Automated releases stay deferred (docs/release-automation.md), which also says to keep validation separate from anything that has release credentials.

## First CI run (PR #6)
The workflow ran on GitHub for the first time and found two real problems, both now fixed on the branch. Still In progress until a run is green on every platform.

- **Ubuntu passed everything**, including the packaged-app tests against a real Linux package.
- **macOS: a real product bug.** project_initialize failed with "Path resolves outside the project" for a folder that did not exist yet under /var/folders/..., because macOS keeps temp folders behind a symlink (/var -> /private/var). resolveProjectRoot left the not-yet-existing root unresolved, so every later real-path check disagreed with it. Any symlinked parent reproduces this on every platform, including a Windows junction, so it is covered by a new test (packages/core/src/paths.test.ts). Fixed by resolving the nearest existing ancestor and keeping the missing tail.
- **Windows: line endings.** Eight editor-preservation tests compare files byte for byte against LF fixtures, but the Windows runner checks files out as CRLF. Reproduced locally by re-checking out the fixtures with autocrlf on. Fixed with a narrow .gitattributes pinning only those fixtures to LF.

**Not yet seen:** a green run. macOS's packaged-app step never ran because the earlier step failed, so my guess at the macOS unpacked-app path is still unproven.

## Handoff
**What changed:** .github/workflows/ci.yml validates every pull request to main and every push to main on Windows, Linux and macOS (fail-fast off): frozen-lockfile install, MCP bundle build, pnpm check (lint, formatting, typecheck, all tests), package the desktop app, then rerun the packaging tests against the real package with REQUIRE_PACKAGED_APP=1 so they fail instead of skipping. Read-only permissions, no secrets, no publishing, actions pinned to commit SHAs, a newer push to the same PR cancels the older run. The packaged-app test now finds the package on each OS. README documents it. Two bugs the first run found are fixed: resolveProjectRoot on a not-yet-existing folder behind a symlink (a real macOS bug, now tested), and CRLF checkout of the byte-exact editor fixtures on Windows (.gitattributes).

**How it was checked:** the second run on PR #6 is green on all three platforms. I read the logs, not just the status: the packaged-app tests ran (3 tests, none skipped) on Windows, Linux and macOS, so my guess at the macOS package path was right. Locally, pnpm check is green; both bugs were reproduced locally first and the new test failed before the fix.

**Not verified:** nothing has been launched as a window on Linux or macOS, and no installer (NSIS, DMG, AppImage, deb) has been built anywhere. CI proves the app builds, packages and that the bundled MCP server runs from the package, not that the window opens. The workflow has only run on a pull request so far, not on a push to main.

**For you to do:** the workflow reports but cannot block a merge. To require it, turn on branch protection for main with required status checks in the repository's GitHub settings; the three check names are "Check and build (windows-latest / ubuntu-latest / macos-latest)". Decide whether all three should be required, or Windows only while Linux and macOS settle.
