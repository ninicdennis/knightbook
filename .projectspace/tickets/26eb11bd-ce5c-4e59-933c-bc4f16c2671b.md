# Create a ticket from the board

## Intended outcome
The user can add a ticket from the Backlog column without an AI tool or an external editor.

## Acceptance criteria
- A New ticket action on the Backlog column opens a form with a required title, an optional type (Feature, Bug, Task or none) and an optional body.
- The body starts from the board's usual shape: Intended outcome, Acceptance criteria, Notes.
- The new ticket is written through the same core create function and write lock MCP's ticket_create uses, lands at the end of the backlog order, and opens in the detail view.
- An empty title cannot be submitted, and a failed write is shown with its reason instead of silently closing the form.
- Keyboard only: the action and form are reachable and submittable without a mouse.

## Notes
Found while surveying the app on 2026-09-23: the host has no ticket-creation IPC operation, so tickets can only be created through MCP or by hand. Pairs with the source-editing ticket for changing a ticket after it exists.

## Handoff
**What changed:** A "+" button labelled "New ticket in Backlog" in the Backlog column header opens `NewTicketDialog`. It has a required title (autofocused, Enter submits), a Type select (No type plus all five types, since Research and Documentation landed in a74a2e70 at the same time), and a monospace Markdown body prefilled with Intended outcome / Acceptance criteria / Notes. The ticket is written as `# <title>` followed by those sections, matching the rest of the board. The new contract operation `createTicket` (`src/shared/ticket-create-contract.ts`, `src/main/ticket-create-ipc.ts`) validates on the host and calls core `createTicket`, the same function and write lock as MCP's `ticket_create`. The ticket is not added to the manual order, so like an MCP-created one it sorts after every ordered ticket by creation time, which is the end of the backlog. On success the board is replaced from disk and the ticket opens in the detail view. On failure the form stays open and shows the host's message.
**How it was checked:** `NewTicket.test.tsx` covers the prefilled sections and default No type, an empty or whitespace title keeping submit disabled, successful create with the trimmed title and chosen type opening the detail dialog, a failed write keeping the form and its text, and the fully keyboard path (focus the button, Enter, type, Enter). `src/main/ticket-create.test.ts` covers host validation: trims the title, rejects empty or missing titles, non-text bodies and unknown types. `pnpm check` passed. In the board preview: created a Documentation ticket with the keyboard only, saw it open in the detail view, and saw the `?createFails` path keep the form with its reason at 900×650 in light.
**Not verified:** The real Electron window, since the running packaged app is an older build (see 5ebdd851). With the preview pane hidden, my first keystrokes were lost while the dialog was still animating open. The unit test shows focus lands in the title, but please try typing immediately after opening in the real app.
**For you to check:** In the app, press "+" on Backlog, create a ticket with a type, and confirm it opens and sits at the bottom of Backlog. Check that the file in `.projectspace/tickets/` looks like the others.
