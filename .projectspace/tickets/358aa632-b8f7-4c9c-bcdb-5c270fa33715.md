# Accessibility and no-JavaScript pass across the website

## Intended outcome
Every page template meets the spec §8 accessibility checks, and downloads and instructions work with JavaScript off, with automated tests that keep it that way.

## Acceptance criteria
- Playwright smoke tests cover the home, download, docs index, one guide, releases, privacy and 404 pages at a narrow (375px) and a wide (1440px) viewport, and fail on horizontal page scroll.
- An automated accessibility scan (for example axe) runs in those tests with no serious or critical violations.
- A test with JavaScript turned off reaches every download link and the full text of a guide.
- Checked by hand and recorded on this ticket: keyboard-only navigation, visible focus, skip link, heading order, meaningful link names, alt text, reduced motion, contrast in light and dark, 200% zoom, and long platform names and filenames.
- The tests run in CI as part of the website checks.

## Notes
Spec §8. Keep it to a few focused Chromium tests, in line with the project's testing defaults.

## Accessibility record (2026-10-06)
Checked against the built site: `pnpm preview:website`, plus the test build with fixture releases 0.3.0 stable and 0.4.0 preview. Chromium 1234 on Windows. Pages checked: home, download, docs index, both written guides, releases and the 404 page. Items are scripted unless marked otherwise; the scripted keyboard pass stood in for pressing Tab by hand.
- **Keyboard and visible focus:** tabbed through every stop on six pages in light and dark at 1440px: home 24, download 11, docs index 17, guide 30, releases 11, 404 15. Each stop showed a focus outline or ring and was on screen.
- **Skip link:** first in the Tab order, on screen when focused, leads to `#main`. Automated test.
- **Heading order:** one `h1` per page and no skipped levels on all seven pages.
- **Link names:** no empty or vague link text ("here", "more", and so on).
- **Alt text:** no `img` without `alt`.
- **Reduced motion:** with `prefers-reduced-motion: reduce`, the longest transition on the homepage is 0.01 ms.
- **Contrast, light and dark:** axe's colour-contrast rule passes on every page in both schemes at both widths. It does not cover focus and hover colours.
- **200% zoom:** every page fits at 640 CSS px, which is a 1280px window at 200%, with no sideways scroll.
- **Long platform names and filenames:** the download page at 375px with fixture filenames such as `Knightbook-0.4.0-windows-x64.exe`, 64-character checksums and every `details` panel open: no sideways scroll. Filenames longer than about 33 characters were not tried.

## Handoff
**What changed:**
- New `apps/website/src/layout/site-accessibility.test.ts`, using Vitest with `playwright-core` and `@axe-core/playwright` (new website devDependencies).
  - It builds the site once with fixture release data, serves it as a static host would (including a 404 status), and checks each page at 375px and 1440px in light and dark.
  - Before measuring, every `details` panel is opened. A page fails on sideways page scroll, and on any serious or critical axe finding.
  - A skip-link test, a 404-status test, and JavaScript-off tests: every download link on `/download/`, including the preview behind its native `details`, and every section of a guide.
- Without Chromium these tests skip. `REQUIRE_WEBSITE_BROWSER` turns the skip into a failure, mirroring `REQUIRE_PACKAGED_APP`. `KNIGHTBOOK_CHROMIUM_PATH` lets a local run use a Chromium already installed.
- `.github/workflows/ci.yml`: the `check` job installs Playwright's Chromium and sets `REQUIRE_WEBSITE_BROWSER`.

**How it was checked:**
- Locally, with `KNIGHTBOOK_CHROMIUM_PATH` set to Chromium 1234, all 29 tests pass.
- A deliberate `body { min-width: 520px }` made all six 375px page tests fail. It was reverted.
- Plain `pnpm check` passes and skips the 29, as designed. Lint, format and typecheck are clean.
- Verifier: covered 3 (axe, JavaScript off, CI), weakly covered 1 (the page list, because privacy is missing), and the hand-check record was not yet on the ticket. Since then:
  - the skip-link check is fixed to use the on-screen position, since `isVisible()` passed off screen;
  - panels are opened before measuring;
  - the build hook has 240 s for slow Windows runners;
  - the record above was added.

**Not verified:**
- **No privacy page exists yet** (ticket 1aefd5aa), so the first criterion is not fully met. Add `['privacy', '/privacy/']` to `PAGES` when that page lands.
- These tests have not run in CI yet. Locally they ran against Chromium 1234, not the 1243 build that playwright-core 1.63.0 installs in CI. Every CI run downloads Chromium, with no cache.
- A Windows timeout in the build hook is the likeliest flake.
- The hand checks were scripted, not done with a physical keyboard or a screen reader.
- Adding the packages locally re-linked a hoisted changelog preset and broke the release-version tests until a forced reinstall. A clean install is unaffected. Filed as d483e78f.
