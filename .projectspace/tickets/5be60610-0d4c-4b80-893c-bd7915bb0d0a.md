# Show Markdown changes since review for documents and tickets

## Intended outcome
The user can immediately see what changed since their last review without rereading an entire document or ticket description.

## Acceptance criteria
- Add a discoverable read-only Changes view alongside normal reading for both documents and tickets. Compare current canonical Markdown with the most recent human-reviewed source, not Git HEAD or the previous save.
- Reuse existing review snapshots and reviewedSource; label the baseline review time and current revision. Opening the comparison never marks content reviewed or tickets Done.
- Default to a unified line diff with clear additions/removals, line numbers, nearby context, and expandable unchanged sections. A single changed line in a long document is immediately visible. Color is supplemented with text/signs and accessible labels.
- Retain frontmatter changes in the comparison, while making ticket bookkeeping distinguishable from its description. Provide faithful source comparison and preserve existing rules for what invalidates review; do not hide substantive metadata edits.
- Handle unreviewed content, identical source, missing/corrupt snapshots, and errors explicitly; never pretend an absent baseline is an empty document.
- Render untrusted source as escaped text. Bound diff computation for large or highly divergent inputs and provide an explanatory fallback. Handle line endings and final-newline differences predictably.
- Refresh or flag a stale comparison if content changes while open. A subsequent review must correspond to the revision actually shown, or require a reload, rather than silently approving unseen edits.
- Keep controls and content usable with keyboard, both themes, narrow windows, and zoom.
