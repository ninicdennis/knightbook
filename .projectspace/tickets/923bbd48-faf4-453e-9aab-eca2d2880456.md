# Redesign the website header and footer

## Intended outcome
The shared website shell looks like a finished part of Knightbook, with a legible brand, deliberate navigation spacing, and a useful grouped footer. It works on the homepage and 404 in both appearance schemes and can be implemented next without waiting for release data.

## Acceptance criteria
- Follow the header/footer sections of the linked design brief: a 72–80px desktop header aligned to the 1120px page grid, visibly sized approved PNG artwork, clear wordmark, quiet navigation, and the existing Download page action.
- Use the existing canonical PNG and image pipeline (or existing deterministic derivation where needed to remove transparent margin). No traced, recolored, redrawn, or replacement logo.
- At narrow widths, brand and Download remain visible, and the existing native details/summary Menu opens into deliberate full-width links. At 320px and 200% zoom, text and controls reflow without clipping or page-wide horizontal scroll.
- The footer uses a brand/one-line-description block, Product and Guides groups, and a restrained utility row only when destinations exist. Header/footer destinations come from shared definitions; no fake legal entity, license, support, source-repository, privacy, or guide link is invented.
- Retain the existing top-level navigation destinations. Planned routes not yet delivered are explicitly recorded as unavailable in the private-preview handoff; this ticket does not claim that they work or add placeholder pages. New footer destinations render only once built/confirmed.
- Keep the shared shell consistent on homepage and 404, with accessible navigation names, actual-current-page indication where applicable, the skip link first, visible focus, and comfortable action targets.
- Preserve no-JavaScript navigation and the mobile menu. Extend the existing built-HTML layout tests for the final structure rather than adding a new framework.
- Capture both schemes at 1440px, 1024px, 768px, 390px, and 320px; check the open menu, keyboard use, 200% zoom, and the 404. Normal text reaches 4.5:1 contrast and large text/essential control boundaries 3:1.
- Run pnpm check and pnpm --filter @knightbook/website build; record visual evidence and any unavailable routes in the handoff.

## Handoff

**What changed.** The work is on branch `feature/website-shell` and is not committed yet. Everything is in `apps/website/src`, plus a note in the technical design ("The public website"). No dependencies were added, and no app paths changed, so merging releases nothing (D-041).
- **`layout/navigation.ts`** defines every destination once (`destinations`): Home, Download, How it works, Documentation, Releases. The header links, the Download action, the footer groups (Product: Download, How it works, Releases; Guides: Documentation) and the 404 all pick from it. `utilityLinks` (Privacy, License, Support) is empty, so that row is not drawn. `isCurrentPage` sets `aria-current` only when a link's page is the one shown, never for the How it works anchor.
- **`layout/logo.ts`** uses `apps/desktop/build/icon.png`, the desktop app's existing deterministic crop of the approved PNG made by `derive-icon.cjs`. The canonical PNG's artwork fills about half its square (632×802 of 1254), so at 32px the visible mark would have been about 20px. The crop's artwork fills 96% of its height. Nothing is redrawn or recoloured. The favicon uses it too.
- **`SiteHeader.astro`:**
  - 76px minimum row height, brand with a 32px mark and 20px semibold wordmark (11px gap);
  - muted 16px links with a 28px gap, darkening with an underline on hover or `aria-current`;
  - a 44px-tall Download with an 8px radius;
  - all targets 44px.
  - Below 720px: the brand and Download keep the first row, and the native `<details>` Menu sits on a ruled second row. It opens into full-width 44px links with dividers.
- **`SiteFooter.astro`:** quiet surface with a top rule and 56px padding. A brand block (28px mark, "Knightbook", "Project documents and a work board, together.") sits on the left and the two groups on the right. On phones they stack, with the groups in two columns. Links are 40px tall and underline on hover. There is no © or legal text.
- **`base.css` and `tokens.css`:** the page grid is 1120px of content plus a 16, 24 or 32px gutter by width (`--kb-gutter`), so the header, content and footer share one edge.
- **`404.astro`** uses the shared destinations.
