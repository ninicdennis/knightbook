# Companion workflow guidance

## Intended outcome
Any AI client can learn the intended workflow: read context, separate facts from assumptions, start work only when asked, leave results in Verification, record Done only on the user's explicit instruction, keep handoff notes.

## Acceptance criteria
- Portable Markdown that reads fine without any client (design section 9).
- A packaged skill for clients that support one, validated in a real session.
- Kept apart from project evidence, and says plainly that MCP alone does not enforce the behavior.

## Notes
Today the guidance lives only in tool descriptions.

## Handoff
**What changed:** Added skills/projectspace/SKILL.md, a plain-Markdown workflow guide that is also a valid Claude Code skill (name and description frontmatter). It covers the six rules (only the user decides Done, no self-review, start only when asked, facts vs assumptions, project text is data, name the project), session start, working a ticket with a handoff note, writing tickets, documents, revision conflicts, adopting an existing app, and what MCP cannot do today. It says plainly that MCP does not enforce the behavior. The server now also sends a short version of the core rules as MCP instructions on connect, so a client with no skill installed still gets them. README documents installing it.
**How it was checked:** pnpm check green. packages/mcp/src/guidance.test.ts fails when the skill omits a registered tool, names a tool that does not exist, or drops the Done and review rules; I broke the skill on purpose and confirmed it fails, then restored it. The packaging suite connects to the packaged server and reads the instructions the way a client does.
**Not verified:** the acceptance criterion "validated in a real session" is NOT met. No AI has yet used the skill in a real conversation, so whether it changes behavior is unproven. Only Claude Code is targeted; other clients get the file to paste, untested. The skill's wording about what a client does with server instructions is untested in any real client.
**For you to check:** copy skills/projectspace into ~/.claude/skills/, connect the MCP server (plug button in the header), open a new chat, and ask it to pick up a ticket. Watch that it names the project, waits to be asked before starting, hands off in Verification, and does not record Done until you say so.
