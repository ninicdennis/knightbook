# Create a document through MCP

## Intended outcome
An AI tool can add a new project document without needing separate filesystem access.

## Acceptance criteria
- A tool creates a new Markdown document at a project-relative path and registers it, refusing to overwrite an existing file.
- It works for a nested path the user invented, creating intermediate folders.
- The specification's "document from an optional template" is either provided or explicitly dropped, with the decision recorded in the project's documents.
- The workflow skill's "What you cannot do through MCP today" section is updated to match.

## Notes
Found running the specification validation scenario (ticket 2e4a254f), steps 1 and 14.

`document_write` edits an existing document and cannot create one, and `documents_include` only registers a file that is already there. Both scenario steps were completed by writing the file with a separate file tool and then including it, which works but assumes the AI client has filesystem access to the project. A client with only this MCP server cannot capture an idea or a specification as a document at all, which is step 1 of the scenario.

Nothing here is broken; this is a missing capability the scenario expects. No template mechanism exists either, so the "create a document from an optional template and freely change its structure" half of step 14 has nothing to exercise.
