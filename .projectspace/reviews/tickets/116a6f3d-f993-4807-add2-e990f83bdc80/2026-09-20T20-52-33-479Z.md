# Split App.tsx

## Intended outcome
The window's root component is back under the project's file size limit, with the ticket operations it owns moved somewhere they can be read and tested on their own.

## Acceptance criteria
- `apps/desktop/src/renderer/App.tsx` is under 300 lines, and nothing extracted from it exceeds that either.
- The ticket operations it currently holds — move, set type, reorder, review, complete, report and resolve a verification issue — move out together with the `apply` helper that gives them their shared conflict and error handling. They belong to one responsibility and must not be split across two places.
- Screen state, the dialogs, the keyboard shortcut and the view switch stay where they are, or move deliberately rather than as a side effect.
- Every existing test passes unchanged. This is a rearrangement: no behaviour, wording, or IPC call may change, and no test may be rewritten to accommodate the new shape.
- Conflict handling stays exactly as it is: a `revision_conflict` still reloads the project first and then explains, in that order, because reloading clears any standing message.

## Notes
Found while adding the ticket-type control in `9507568c-7ec9-445b-adac-b016ede99794`. App.tsx was already 515 lines, over the 400-line hard limit in the project's own guidance, before that change added another 15. The ticket-type work deliberately did not refactor it: growing an already oversized file by fifteen lines is a smaller problem than reshaping the window's root component inside an unrelated change.

The natural seam is a hook, `hooks/useTicketActions.ts`, taking the open screen and the loader and returning the callbacks plus `busyTicketId` and `actionError`. `hooks/` already exists and holds `useRefreshOnFocus`.

This is maintenance with no user-visible outcome, so it is worth doing before the next feature lands in that file rather than after.

## Verification
Run `pnpm check` and confirm the same test count passes with no test file modified. Compare `git diff --stat`: App.tsx should shrink by roughly what the new file gains, with no third file changed except imports. Open the app or the board preview and exercise one of each operation — a move, a type change, a reorder, a review, and a completion — confirming the busy state, the error banner, and the conflict message all still appear.
