# Copy the MCP configuration in the format of Claude, Codex, or OpenCode

## Intended outcome
The user picks their AI client and gets a snippet they can paste straight into that client's config file, with nothing to reshape by hand.

## Problem
`CopyMcpConfig.tsx` copies one inner object, `{ command, args }`. That is the Claude shape without its `mcpServers.knightbook` wrapper, and it does not work in other clients. OpenCode wants `mcp.knightbook` with `type: "local"` and a single `command` array (program followed by its arguments). Codex wants TOML. The launch command is the same for all three; only the wrapping differs. Found on 2026-09-24 while connecting OpenCode by hand.

## Acceptance criteria
- Replace the single copy control with a choice of client: Claude, Codex, OpenCode. Keep the compact footer icon usable.
- Each option copies a complete snippet, outer key included, so it can be pasted without wrapping:
  - Claude (Claude Code, Claude Desktop): JSON `{ "mcpServers": { "knightbook": { "command", "args" } } }`. Consider also offering the `claude mcp add knightbook -- ...` command line.
  - Codex: TOML `[mcp_servers.knightbook]` with `command` and `args`.
  - OpenCode: JSON `{ "mcp": { "knightbook": { "type": "local", "command": [...], "enabled": true } } }`.
- Say where the snippet goes for each client (which file, and whether an existing server list should be merged rather than duplicated).
- Build the snippets in one pure function in `apps/desktop/src/shared` from the existing `McpLaunchCommand`. No new contract operation; the renderer already has everything it needs.
- Unit tests for each format, including Windows paths (backslashes escaped in JSON, TOML strings that need no escaping) and paths containing spaces.
- Check each format against the client's current documentation during implementation and record the checked date and source in the technical design as a numbered decision. The formats above are from memory and are unverified.

## Notes
- Clients other than these three still need a fallback. The generic `command` and `args` values are enough for most of them.
- These formats belong to the clients and can change without notice. Keeping the list to three limits that exposure.
- Overlaps with 9f4177e9 (Bundle the workflow skill and add guided AI setup), which calls for client-specific connection instructions as part of a larger onboarding flow. This ticket is the smaller, standalone slice: correct per-client snippets from the existing copy control. 9f4177e9 can build on it.

## Handoff
**What changed:** `apps/desktop/src/shared/mcp-client-config.ts` builds every snippet from `McpLaunchCommand` in one pure function, `mcpClientSnippets`: Claude Code or Claude Desktop (JSON `mcpServers.knightbook` with `type: "stdio"`), Codex (TOML `[mcp_servers.knightbook]`, literal strings so Windows backslashes need no escaping, an escaped basic string when a path holds `'`), OpenCode (JSON `mcp.knightbook`, `type: "local"`, one `command` array, `enabled: true`), and "Another client" with the plain command and arguments. Each carries where it goes and to merge rather than duplicate. `CopyMcpConfig.tsx` is now a button opening that menu; after copying, a line below it says "Copied for Codex. Paste it into ~/.codex/config.toml…", or that nothing was copied if the clipboard refused. The AI setup dialog's hand-written per-client text was replaced by a pointer to the menu, so the two cannot drift. No contract operation. The desktop test config now includes `src/shared/**/*.test.ts`. Decision D-026 in the spec, and sources in technical design section 9.

**Formats checked 2026-09-25:** code.claude.com/docs/en/mcp (Claude Code; `type: "stdio"` shown in `.mcp.json`), learn.chatgpt.com/docs/extend/mcp (Codex; redirected from developers.openai.com/codex/mcp), opencode.ai/docs/mcp-servers and /docs/config (OpenCode, including file locations and that its configs merge). All three matched the ticket's formats, apart from Claude now showing `type: "stdio"`.

**Deviations:** The `claude mcp add … --` command line was not offered: quoting a path with spaces differs between PowerShell, cmd and POSIX shells, so one copied line would be wrong for some users. The compact footer icon no longer exists: every placement (MCP panel, AI setup dialog, folder setup) already used the labelled button, so the unused icon variant was removed rather than given a menu.

**How it was checked:** `src/shared/mcp-client-config.test.ts` parses each snippet back (JSON with `JSON.parse`, the Codex table with a small reader) for Windows paths with spaces, a path containing `'`, and macOS/Linux paths. `src/renderer/CopyMcpConfig.test.tsx`: the four menu choices, the exact Codex text on the clipboard with the where-it-goes line, and a refused clipboard reported as nothing copied. In the board preview the menu opens above the button inside the MCP panel, the panel stays open after choosing, and the refused-clipboard message showed (the preview pane was not focused, so its clipboard write was refused). Full `pnpm check` passes.

**Not verified:** A successful copy in the packaged app, and pasting each snippet into the real clients. The Claude Desktop file name comes from general knowledge, not from the pages checked.

**For you to check:** After repackaging, copy for OpenCode, paste into `~/.config/opencode/opencode.json`, and confirm OpenCode connects; the same for Codex if you use it.
