# Edit a ticket's title and body as Markdown source

## Intended outcome
The user can correct a ticket's title and wording in the app through a plain Markdown text area, without waiting on the formatted editor.

## Acceptance criteria
- The detail view offers an Edit action that shows the title and the Markdown body as source; frontmatter is not shown and never altered.
- Saving sends the revision that was read. If the file changed since (MCP, another editor), the save is refused and the user sees that the ticket changed, with the option to reload; nothing is overwritten.
- Opening and cancelling, or saving without changes, does not rewrite the file.
- A meaningful body change on a reviewed ticket shows changed_since_review, the same as an MCP edit.
- Unsaved edits are not lost silently when the dialog is closed; the user is asked first.

## Notes
The formatted editor (b217a95f) is blocked on a Milkdown fix. T-001 prefers a formatted editor for documents and leaves a source mode optional; the user approved source editing for ticket content on 2026-09-23 as a separate, smaller step. It should not pre-empt the document editor decision.

## Handoff
**What changed:** Branch `feature/ticket-source-editing`, uncommitted.
- New contract operation `editTicketContent` (`shared/ticket-edit-contract.ts`), handled as `ticket:editContent` in `main/tickets/ticket-edit-ipc.ts`. The host validates the title (non-empty, one line) and body, writes nothing when both match the file (line endings ignored), keeps the file's own CRLF/LF endings on a real change, and calls core's existing `updateTicket`, so a stale revision is refused as `revision_conflict` there. No change to core or MCP.
- Detail view: an "Edit title and text" button (read mode only) swaps the reading region for a Title field and a monospace Body textarea (`renderer/tickets/TicketSourceEditor.tsx`, state in `useTicketSourceEdit.ts`). The editor opens on the dialog's fresh read and saves against that read's revision. While editing, the blocker, moves, type and the Back link are hidden, because each would either close the dialog or change the revision the draft is saved against.
- On a conflict the draft stays, an alert says nothing was overwritten, the board reloads, and "Discard my edit and load the current version" shows the newer text. Save is not offered again, since it would be refused the same way.
- Close, Escape, click-outside and Cancel ask "Discard your unsaved edit to this ticket?" when there is unsaved text, and close straight away when there is none.
- To keep `TicketDetailModal.tsx` from growing (303 lines, it was 304): the ticket read moved to `useTicketDetail.ts`, and the related-document failure notice moved into `RelatedDocuments` itself. Neither changes behaviour.

**Not verified:**
- Not tried in the real Electron app against a real project, only in unit tests and the stub-data board preview; the save and conflict paths were not exercised end to end through IPC. No test calls the `ticket:editContent` IPC handler itself; it is checked through `parseContentEdit` and `saveTicketContent`.
- The app was not repackaged, so no packaged build contains this feature. (Correction, 2026-09-28: this note first said nothing was packaged; an older package existed and its tests ran.)
- If the ticket disappears from the board while the editor is open (archived or deleted elsewhere), the dialog unmounts and the draft is lost without a prompt.
- Criterion 1's wording: the title lives in the frontmatter, so a title edit does change the frontmatter (`title`, and `updated_at` on any save). Everything else in it is left byte for byte.
- The body's H1 is not kept in step with the title; editing one does not change the other.

**For you to check:** Open a ticket in the app, use "Edit title and text", change the wording and save; the board and the dialog should show it straight away. Then open the editor, change the ticket through MCP (or in another editor), and save: it should be refused with your text kept. Try closing with unsaved text. On a ticket you have reviewed, a real edit should flag it for renewed review.
