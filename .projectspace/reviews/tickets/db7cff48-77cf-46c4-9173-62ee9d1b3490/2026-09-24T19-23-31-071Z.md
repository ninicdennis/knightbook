# Working navigation from project links

## Intended outcome
Clicking or keyboard-activating a Markdown link opens the referenced document, ticket, or heading when the target is supported and available. Failed navigation explains why instead of silently doing nothing.

## Evidence
User reports links look clickable but lead nowhere. Source inspection confirms TicketDetailModal renders bodies with `renderMarkdown(detail.body, 'ticket.md')`; relative paths are resolved from that fictional root-level file. markdown.ts classifies every internal path as a document, drops fragments, and rejects fragment-only links. MarkdownBody and ticket detail only dispatch internal document callbacks. These confirmed gaps do not establish that all existing related-document buttons or all document-to-document links fail; reproduce each path during implementation.

## Acceptance criteria
- Resolve standard relative Markdown links from the actual source document/ticket file location. Structured related_documents entries remain project-relative, not body-relative. Use the actual canonical record location, not an assumed filename if records can be renamed.
- Open an included Markdown document in Documents; resolve a canonical ticket file to its validated stable ticket ID and open the existing ticket-detail experience. Support document-to-document, document-to-ticket, ticket-to-document, and ticket-to-ticket navigation. Handle same-target navigation deliberately rather than leaving a stale view.
- Preserve fragments for same-file and cross-file links. Generate deterministic heading IDs, including duplicate headings, and scroll/focus the destination after rendering. Document the supported heading convention; a missing heading gives feedback while leaving the target readable.
- Correctly handle spaces and percent-encoded filenames without double decoding; normalize and validate paths at the host boundary, including traversal, Windows separators/absolute paths, and symlink escapes. Keep sanitization and unsafe-protocol blocking intact.
- Reuse current project-boundary validation and document inclusion rules. Missing/unreadable targets, excluded documents, non-Markdown files, and unsupported destinations report a specific visible result. Do not silently add documents, open arbitrary local files, or load record files as raw document frontmatter.
- Keep HTTP(S) links opening through the existing validated host external-browser action; display returned errors. Do not enable arbitrary file/custom-protocol links to work around internal navigation.
- Route overlays and document selection deliberately so a newly opened target is visible, not behind the previous ticket. Provide a lightweight return-to-source action for internal cross-record navigation, preserving useful selection/scroll state and sensible focus; no full browser-history framework required.
- Keep navigation scoped to the originating checkout. Late reads after project/target switching cannot replace the destination with stale content. Following links changes no ticket status/review or document inclusion state.
- Update README/workflow link examples to use ordinary source-relative Markdown paths. Explicitly test `../../docs/ui-ux-design-direction.md` from a canonical ticket and a sibling `<ticket-file>.md` link. Bare UUID/prose mentions are not automatically converted into links.

## Scope and coordination
Extend existing classifier/MarkdownBody, host validation and app navigation; no new dependency, OS URL registration, custom Markdown syntax, cross-project linking, or editor implementation is required. Coordinate with UI layout tickets for TicketDetailModal/DocumentsView. This ticket is conceptually a Bug; the proposed structured ticket-type feature is not a prerequisite.

## Verification
Add tests for all four source/target combinations, related-document buttons, encoded names, same-file and cross-file fragments, missing targets/anchors, excluded documents, unsafe URLs/traversal/symlinks, and host errors. Test end-to-end user interaction rather than only generated HTML. Reproduce long-ticket links and keyboard activation in preview and the packaged desktop app; validate HTTP(S) opening in the real host. Run pnpm check. Diagnosis is source-backed; packaged reproduction remains future work. See linked research for CommonMark and Electron primary sources.

## Handoff
Branch `feature/review-changes-diff`, uncommitted, in the same working tree as the finished diff ticket 5be60610. No new dependency.

**What changed:**
- Core `packages/core/src/links.ts`: `resolveLinkDestination(project, path)` answers from disk with an included Markdown document, a ticket file whose ticket exists, or `unavailable` with a reason: `outside_project` (traversal, absolute or drive paths, backslashes, symlink escapes), `reserved` (other `.projectspace` records), `not_markdown`, `not_included` (exists, not in the manifest), or `not_found`. It reads only and never includes anything. Exposed as the `link:resolve` / `resolveLink` contract operation.
- Renderer `markdown.ts`: links resolve from the real source file. Tickets use `.projectspace/tickets/<id>.md` instead of the old `ticket.md` placeholder. Percent-escapes are decoded exactly once, and escaped separators, malformed escapes and backslashes are refused. Fragments are kept (`data-fragment`), and a bare `#x` is a same-file anchor. Headings get GitHub-style ids (`user-content-` prefix, `-1`/`-2` for repeats). The sanitizer allowlist now has `data-link`/`data-fragment` in place of `data-document`; everything else about sanitizing is unchanged.
- `MarkdownBody`: dispatches link / anchor / external, scrolls to and focuses the destination heading, and shows an inline notice for any failure (unavailable target, missing heading, external-open error).
- Navigation: `hooks/useLinkNavigation.ts` resolves through the host, opens the document (Documents view) or the ticket dialog, and drops replies superseded by a newer link or a project switch. It keeps one step back, shown as "Back to …" only on the destination (`BackToSource.tsx`). Ticket→ticket replaces the dialog (keyed by id). Related-document buttons go through the same host check and show failures inside the dialog. A newly opened document starts at the top unless the link named a heading.
- Refactors to stay under limits: `TicketDetailHeader.tsx` split from `TicketDetailModal.tsx` (now 303 lines); the preview stub's document operations moved to `preview/documents-stub.ts` and `preview/record.ts`.
- Docs: README "Document content is untrusted" section gains the link rules, heading convention and an examples table; `skills/projectspace/SKILL.md` gains ticket-body link guidance vs project-relative `related_documents`; technical design gains "Following links as built (2026-09-24)" in section 1.

- Links to tickets archived off the board open like any ticket; not separately tested.
- macOS and Linux not checked.
