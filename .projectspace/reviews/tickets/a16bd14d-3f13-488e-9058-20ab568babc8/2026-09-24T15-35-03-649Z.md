# Group Documents into collapsible folders with custom titles

## Intended outcome
The Documents sidebar shows a readable nested folder hierarchy, with optional names such as Documentation for docs, so users can collapse sections and quickly find files.

## Acceptance criteria
- Derive nested folder groups from the real paths of included Markdown files. Root files remain directly accessible; distinguish duplicate basenames through their path context.
- Let the user assign, edit, and clear an optional title for each folder, including nested folders. Persist titles in project-local repository-owned metadata keyed by normalized project-relative folder path. A label never renames or rewrites the source folder/files.
- Expand/collapse groups independently and retain expansion appropriately per project as local view state. Selecting a document or following an internal link makes its location discoverable, including when ancestors were collapsed.
- Preserve documents_include, includedVia, overlap deduplication, exact removal scope, review status, external editing, and canonical path resolution. Collapse is never removal, and removal of inclusion never deletes source files.
- Handle missing files, unreadable paths, and stale labels after external folder renames visibly and without destructive cleanup. Validate metadata paths using existing project-boundary rules.
- Provide keyboard-accessible tree navigation, visible focus/selection, named expand controls, and expanded/selected state for assistive technology. Evaluate Mantine Tree already available in the UI stack before writing custom tree behavior.
- Reuse the Board palette and coordinate with the existing Documents responsive-layout ticket. Verify labels and long paths in both themes, narrow views, and zoom.

## Notes
User confirmed real folders with custom titles in project metadata on 2026-09-21. Current documents.ts flattens recursive paths and DocumentsView.tsx maps them into a flat NavLink list. A sparse folder-label map in .projectspace/project.md is the recommended starting point; preserve unknown metadata and existing projects during schema evolution. Expose labels in relevant document metadata APIs so AI and app observe the same organization.
