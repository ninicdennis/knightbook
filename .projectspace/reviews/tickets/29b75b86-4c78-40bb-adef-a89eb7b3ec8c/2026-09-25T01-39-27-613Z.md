# A ticket's id is readable and copyable

## Intended outcome
The ticket's id can be read and copied from its detail dialog, so it can be named to an AI client or pasted into another ticket's `depends_on`.

## Acceptance criteria
- The open ticket shows its id, and a copy control puts the full id on the clipboard. What is copied is always the whole id, even if what is shown is shortened.
- Copying confirms it happened, and says so if it did not. `CopyMcpConfig.tsx` already does this with Mantine's `CopyButton` and is the pattern to follow.
- The id is the quietest thing in the header. The title stays the strongest, and status, type and review keep the hierarchy they have.
- The copy control is reachable by keyboard and has an accessible name that says what it copies. An icon alone is not enough.
- Nothing about the id is editable, and no new host operation is needed.

## Notes
Ids are how tickets are referred to everywhere outside the board: `depends_on` holds them, the MCP tools take them, and a request to an AI client has to name one. Right now an id is only visible in the app when a dependency is broken, inside the error text in `TicketDetailSections.tsx`, and otherwise has to be read off a filename in `.projectspace/tickets/`.

Technical design section 3 allows the interface to abbreviate an id when that is unambiguous. A short form is easier to read aloud and to match against a filename; a full id is what other tools need. Decide which is shown, keep the copy faithful to the whole thing, and write down the reason.

## Verification
Open a ticket, copy the id, and paste it somewhere: it matches the filename under `.projectspace/tickets/` and the `id` in that file's frontmatter. Reach the control by keyboard and confirm what a screen reader would announce. Check the header still reads title first in both colour schemes and in a narrow window.

## Handoff
**What changed:** The ticket header's record row, now `TicketRecordRow.tsx` (renamed from the `TicketFileRow` added for "Edit externally"), shows the id before that control:
- The first eight characters, in small muted monospace, with the full id in a tooltip.
- A copy icon button whose accessible name is "Copy the full ticket id, <full id>". It changes to "Copied the full ticket id", or to "Could not copy the ticket id" with an inline alert.
- No host operation was added, and nothing is editable.

**Decision:** Show eight characters, because that is how this project's own notes name tickets ("ticket `b217a95f`") and it is the start of the filename. Always copy the whole id, because `depends_on` and the MCP tools need it, so a hypothetical prefix collision could never reach another tool. Recorded in technical design section 3, "Showing a ticket's id as built (2026-09-24)".

**One deviation:** The copy uses Mantine's `useClipboard` hook rather than `CopyButton` as in `CopyMcpConfig`. `CopyButton` gives no way to tell that the clipboard refused, and the ticket asks for that case to be reported.

**How it was checked:**
- Five renderer tests in `TicketId.test.tsx`: the short form is shown and the accessible name carries the full id; clicking writes the full id, and the clipboard reads back the full id with a confirmation; Enter on the focused control copies; a refused clipboard shows an alert and no "Copied"; the title comes before the id in the header.
- Reviewed in `pnpm preview:board` in dark mode and in light mode at 420px wide. Title, then badges, then the muted id row; nothing was clipped.
- The full `pnpm check` is run once for this batch (see the chat summary).

**Not verified:** Not pasted from a real clipboard in the Electron app; jsdom's clipboard stood in, and the preview's stub ids are short words, not UUIDs. No screen reader was run; the announced name is inferred from `aria-label`. Contrast of the muted id was judged by eye, not measured.

**For you to check:** Open a ticket, copy its id, and paste it: it should match the filename in `.projectspace/tickets/` and the `id` in its frontmatter. Tab to the copy control and press Enter.
