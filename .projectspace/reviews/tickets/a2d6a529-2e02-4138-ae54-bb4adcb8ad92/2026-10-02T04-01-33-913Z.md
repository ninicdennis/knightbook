# Release the desktop app only when a merge changes the app

## Intended outcome
Merges that change only the website, the docs, the README or the board no longer publish a new desktop release, and their commits neither bump nor appear in the next app release. A merge that changes what goes into the installers still releases as D-040 describes.

## Acceptance criteria
- One list names the paths that make up the shipped app and its build: `apps/desktop`, `packages`, `skills/projectspace`, the root `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `tsconfig.base.json`, and the CI and release workflows.
- The release workflow starts only when a push to `main` touches one of those paths, so a website-only or docs-only merge runs no macOS or Windows builds.
- When choosing a version, commits that touch none of those paths are ignored: a website `feat:` merged earlier does not turn the next app fix into a minor release, and it is left out of that release's notes.
- A test fails if the workflow's path filter and the list drift apart.
- Recorded as a numbered, dated decision that narrows D-040's "every merge releases", and the maintainers' guide in the release-automation document is updated.

## Notes
Created 2026-10-01. The user asked how to keep website changes from releasing the desktop app, then chose to release only on app changes, which also exempts docs and board merges. A change to `pnpm-lock.yaml` counts as an app change because it can change what the desktop build installs, so the first website PR, which adds Astro to the lockfile, will still release one patch. This must merge before the first website PR.

## Handoff

**What changed.** Branch `feature/release-only-app-changes`, uncommitted. Recorded as D-041 in the specification; D-040 now points to it.
- `apps/desktop/scripts/publishing/app-commits.mjs` (new) holds `APP_PATHS`, the one list of what counts as the app. It is also a semantic-release plugin: before the commit analyzer and the notes generator run, it drops every commit whose changed files (`git diff-tree`, with merge commits read against their first parent) touch none of those paths. `next-version.mjs` now loads it in place of the two plugins it wraps, with the same rules.
- `.github/workflows/release.yml`: `on.push.paths` repeats the list, so a push that changes none of it starts no release run and no macOS or Windows builds.
- `docs/proposals/release-automation.md` ("What causes a release") and AGENTS.md explain the rule.
