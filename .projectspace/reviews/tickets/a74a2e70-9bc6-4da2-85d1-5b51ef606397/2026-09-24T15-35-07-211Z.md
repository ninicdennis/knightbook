# Add Research and Documentation ticket types

## Intended outcome
Make research and documentation work recognizable at a glance through two additional choices in the existing ticket Type selector: Research and Documentation.

## Acceptance criteria
- Extend the existing optional type field with `research` and `documentation`, alongside Feature, Bug, Task, and No type. Keep one optional type per ticket using the current model.
- Define Research as investigation, comparison, or evidence gathering; Documentation as creating, improving, or maintaining written guides and reference material. Task remains available for general work.
- Show readable labels consistently in the selector, board cards, ticket detail, and search results. Suggested presentation: 🔎 Research and 📝 Documentation, with decorative emoji and accessible text following existing badge conventions.
- Support both values consistently through core validation, canonical Markdown persistence, desktop contracts/IPC, and MCP create/update/read/list/search. Update the companion skill and relevant type documentation to describe all five choices.
- Preserve omitted-update and explicit-null clearing behavior, revision conflict handling, and review invalidation rules. Existing typed and untyped tickets remain valid; do not automatically reclassify any existing tickets.
- Keep type independent of workflow status, completion, dependencies, priority, and release versioning. Reuse the existing selector/badges rather than introducing a separate multi-tag system.

## Notes
User requested two new tags, Research and Documentation, as an additional backlog ticket. This ticket records future implementation; it does not enable the types in the running application.
