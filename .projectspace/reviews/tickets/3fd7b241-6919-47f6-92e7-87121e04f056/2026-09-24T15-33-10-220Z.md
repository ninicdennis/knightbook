# The window says which project is open

## Intended outcome
The title bar and the taskbar entry name the open project and the folder it came from, so the right window is findable without bringing it to the front.

## Acceptance criteria
- With a project open, the window title is the project's name followed by the checkout folder's name. The folder is what separates two clones of the same project, which the name alone cannot do.
- With nothing open, and on the welcome, loading, not-a-project and failed screens, the title is `Projectspace` and claims no project.
- The title follows the project: switching projects, completing one-click setup for a new folder, and a name changed in `project.md` and picked up by a refresh all update it.
- The name comes from the loaded project record, not from the folder name, and is not truncated or reformatted beyond what the operating system does on its own.
- Setting the title is a host concern. The renderer asks through a named operation in `src/shared/contract.ts` like every other host call; it does not reach Electron directly.

## Notes
`apps/desktop/src/renderer/index.html` sets a static `<title>Projectspace</title>` and nothing changes it afterwards. The in-window header already shows both the project name and the checkout path, so this is only about what is visible from outside the window.

The skill that guides AI tools in this project tells them to say which project they are in, because two clones look alike. The window should be able to answer the same question.

## Verification
Open a project and read the title bar and the taskbar entry. Switch to another project and back. Set up a fresh folder and confirm the title changes at the point the board appears. Edit the name in `project.md`, refresh, and confirm it follows. Close the project or start from the welcome screen and confirm the plain title returns. Check a long project name does not break the window controls on Windows.
