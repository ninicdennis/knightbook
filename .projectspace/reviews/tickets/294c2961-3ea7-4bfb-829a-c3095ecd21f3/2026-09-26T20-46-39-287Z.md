# Filter the whole board by plan

## Intended outcome
Use one plan selector across all four board columns so separate efforts, such as the website and desktop app, remain easy to follow in the same repository.

## Acceptance criteria
- A visible selector labelled "Plan" above the board offers All tickets, each existing plan, and No plan. All tickets is the initial default.
- Selecting one plan shows the active tickets linked anywhere in its phases, once per ticket. Shared tickets appear under each plan that links them. No plan shows tickets with no plan membership.
- The selection applies to Backlog, In progress, Verification, and Done together. Column counts reflect matching tickets; a board summary shows matching versus total active tickets and provides an easy reset to All tickets.
- The selection is remembered per project across navigation and reopening the app, without leaking between checkouts. If the selected plan no longer exists, fall back to All tickets.
- Each plan offers View on board, which opens the board with that plan selected. An empty plan shows a clear empty filtered view and a way to reset.
- Filtering preserves ticket status, backlog order, plan membership, dependency evaluation, and access to prerequisites outside the selected plan. Archived tickets remain outside the working board.
- Header search, Documents, the Plans list, and MCP access remain project-wide. The selected view does not implicitly scope AI work or change ticket_next.

## Notes
Use the existing plan-to-ticket relationships; no new tags, separate boards, multi-select, or active-plan workflow state. This complements the existing per-column type/state filtering ticket rather than replacing it. If both filters exist, their conditions should combine.

Record the agreed view behavior in the specification and technical design during implementation, including a numbered, dated decision with its reasoning. Verify with multiple plans, a shared ticket, an unassigned ticket, an empty plan, and a dependency outside the selected plan.
