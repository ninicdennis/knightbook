# Create a document from the app, optionally from a starter template

## Intended outcome
The user can create a new Markdown document in a chosen location inside the project, blank or from a small set of optional templates, and it appears in the workspace immediately.

## Acceptance criteria
- The user chooses the file name and folder; the location must be inside the project folder.
- Creating never overwrites an existing file; a name clash is reported and nothing is written.
- A small template set is offered: project definition, specification, decision record. Templates are editable starting points and impose no structure (D-010).
- The new file is included in the workspace and opens in the viewer.
- The core create function is shared with the MCP document-creation ticket (fa05d99e) rather than duplicated.

## Notes
The spec's document organization section asks for creating blank documents or starting from a template. The exact template set was open; the three above are the proposal to confirm when this starts.

## Handoff
**What changed:**
- Documents view: "New" next to "Include" opens a dialog with:
  - Folder, pre-filled with the folder of the document being read, empty for the project's top folder;
  - File name, with `.md` added when missing;
  - Start from: Blank, Project definition, Specification or Decision record;
  - a live "Creates docs/x.md and includes it" line.
- Host: `document:create` (`main/documents/document-create-ipc.ts`) calls core's `createDocument`, the same function MCP's `document_create` uses. Nothing is duplicated. Core refuses outside-project paths, `.projectspace/`, non-Markdown files and any existing file. The host rewords a clash to name the path the user chose, and returns the updated listing. The new document is selected and opens in the reader.
- A refusal keeps the dialog open with what was typed.
- Templates (`renderer/documents/document-templates.ts`) are a title from the file name ("release-notes" gives "Release notes") plus a few headings; the decision record also gets today's date and "Status: proposed". Nothing checks a document against them.
- `IncludedEntries` owns the button and dialog.
- Docs: D-036 in the spec; the "exact set is not yet selected" line now names the set.

**Assumption to confirm:** the template set is the one the ticket proposed. You did not confirm it; I took it because the goal was to proceed without stopping. Change or drop any of them in `document-templates.ts`.
