# Edit a ticket's dependencies and related documents

## Intended outcome
From the ticket detail view the user can add and remove prerequisites and linked documents, which today only MCP can change.

## Acceptance criteria
- Prerequisites are chosen by ticket title from a searchable list; the ticket itself and archived tickets are not offered.
- A change that would create a cycle, or refer to an unknown ticket, is refused with a plain explanation, using the same validation as MCP's ticket_update.
- Related documents are chosen from the workspace's included documents.
- Dependency readiness and waiting notes on the card and in the detail view update immediately after saving.
- The write carries the ticket's revision and handles a conflict the same way other ticket edits do.

## Notes
D-012 and D-014 define dependencies and readiness. Explicit dependency overrides remain an open decision and are not part of this ticket.

## Handoff
**What changed:** Branch `feature/ticket-source-editing`, uncommitted, alongside ticket f9bc5b71's work.
- **Decision D-032** (spec, 2026-09-28, user's choice): MCP's `ticket_update` did not refuse cycles or unknown ids before; it wrote them and readiness reported them. Core's `updateTicket` now refuses a `depends_on` change that *adds* the ticket itself, an unknown id, or a prerequisite that already leads back to the ticket, with code `invalid_dependency`, a plain message naming the chain by title, and nothing written (`packages/core/src/tickets/dependency-change.ts`). References already in a file are still reported, not refused, so a hand-edited bad link never blocks editing the rest. Archived prerequisites are allowed. The app and MCP share this one check. Technical design and `skills/projectspace/SKILL.md` updated; `pnpm build:mcp` rebuilt.
- Two core tests that built cycles through `updateTicket` (`workflow.test.ts`, `verification.test.ts`) now write them by hand through a new `setDependenciesByHand` fixture, since that is the only way such a cycle can now arise.
- App: contract operation `setTicketLinks`, handled as `ticket:setLinks` (`main/tickets/ticket-edit-ipc.ts`): validates both lists, drops repeats, writes nothing when both lists are unchanged, otherwise calls `updateTicket`.
- Detail view: "Edit prerequisites and documents" opens `TicketLinksEditor` under "Depends on": a searchable multi-select of board tickets by title (not this ticket, not archived) and one of included documents (from `listDocuments`). Existing links that would not be offered now stay listed, labelled "(archived)", "Missing: id" or "(not included)", so they can be removed. Refusals show in the dialog with the choice kept; a conflict reloads the board, says nothing was overwritten, and offers "Load the current version". Only one editor (links or source) is open at a time.
- `useTicketActions`: `editContent` and the new `editLinks` share one `saveFromDialog`. The modal's focus-return effect moved to `useReturnFocusToCard.ts` to make room; the modal is 306 lines (304 before both tickets).
