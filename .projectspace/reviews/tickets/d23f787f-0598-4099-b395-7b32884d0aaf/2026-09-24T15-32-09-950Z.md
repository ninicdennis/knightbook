# A coherent, responsive application shell

## Intended outcome
The board, project header, search, and connection footer feel like one application, with a readable project identity and controls that fit smaller windows.

## Acceptance criteria
- Apply shared surface roles from surfaces.css to the app-owned header/footer and controls; preserve the existing board palette and quiet Done treatment.
- Align project identity, centered search where space allows, view navigation, Refresh, and Settings with consistent heights and spacing. Give selected navigation and keyboard focus clear treatments without competing with Next up.
- Long names and checkout paths cannot squeeze search or utility controls offscreen. Keep the full checkout available accessibly; use a deliberate narrow-width reflow and account for the resulting header height in the main layout.
- Keep Ctrl/Cmd+K behavior, search scope, loading states, tooltips, navigation, and MCP status behavior intact. Keep the footer subordinate but legible.
- Reconcile the current light native-window background (#f4f5f7 in window-theme.ts) with the renderer window token (#eef0f4) to avoid a mismatch during resize/startup. Follow the selected light/dark/system scheme without replacing native title/menu controls.
- Reserve space for future Archive navigation through flexible layout, without adding an Archive control in this ticket.
