# Make the top navigation clearer and more approachable

## Intended outcome
Make project switching, page navigation, search, and utilities easier to distinguish and use. Preserve the existing dark palette and typography while improving spacing, labels, and visual hierarchy.

## Acceptance criteria
- Use a roomier two-row header: project identity, search, and Settings in the first row; Board, Documents, and Plans in the second row, with Archive separated at the far right.
- Replace boxed page controls and vertical separators with simple tabs, readable inactive labels, and a clear active indicator such as an underline.
- Make the project name a clearly indicated project-menu trigger. If the current hamburger serves project navigation, consolidate that function here while preserving all existing menu actions.
- Move the full folder path into the project menu, where it remains easy to inspect and copy, including when projects have the same name.
- Keep Archive accessible with an accurate, visually quiet count badge.
- Keep Settings accessible; icon-only controls have accessible names, tooltips, and visible keyboard focus.
- Preserve manual refresh. If it is an occasional utility, expose a labeled Refresh project action in the project menu; if it needs frequent access, retain a visible labeled control. Confirm its role before choosing placement.
- Retain Search tickets wording while search only covers tickets; do not imply project-wide search or expand search scope as part of this work.
- Navigation, menus, search, and utilities remain usable with keyboard input, long project names, and narrow supported window widths, without clipping or overlapping controls.
- Verify navigation, project switching, search, archive access, refresh, and Settings still work; visually check the header at normal and narrow widths and run pnpm check before handoff.
