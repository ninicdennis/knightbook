# Set up the Astro website package with layout and design tokens

## Intended outcome
An `apps/website` workspace package builds a static Astro site with a shared layout, so every later page ticket only adds content.

## Acceptance criteria
- `apps/website` builds to static output with `pnpm --filter @knightbook/website build`, and a local dev/preview command is documented in the README command table.
- Its lint, format, typecheck and tests run as part of `pnpm check`, and CI runs its build.
- A base layout has the header (Knightbook wordmark and logo, How it works, Documentation, Releases, Download), a footer with space for license and support links, and a skip link.
- The mobile header keeps a visible Download action and accessible navigation that works without JavaScript.
- A small token set (background, surface, text, muted, accent, success, warning, danger, border, radius, spacing) in light and dark follows the desktop app's muted blue accent and system typography.
- A useful 404 page exists.
- The pages ship no client-side JavaScript by default.
- Choosing Astro is recorded as a numbered, dated decision in the technical design.

## Notes
The user chose Astro on 2026-09-29: static output, Markdown guides, no JS by default, which fits the no-JS download requirement (spec §8). Follow the feature-folder convention (D-027). Use `docs/assets/knightbook-logo.png` as the only logo source. No analytics or tracking scripts (spec §9).

## Handoff

**What changed.** The work is on branch `feature/website-scaffold` and is not committed yet. The decision is D-042, recorded in the specification and under "The public website" in the technical design.
- **`apps/website`** (new) is an `@knightbook/website` package using Astro 7.3.5. Output is static, with trailing slashes and no telemetry or dev toolbar. Scripts: `dev`, `build`, `preview` (port 4321), `typecheck` (`astro check`), `test` (vitest). The root adds `pnpm dev:website` and `pnpm preview:website`, and `.claude/launch.json` adds `website-preview`.
- **`src/layout`** is the frame every page shares:
  - `BaseLayout.astro`: title, description, a favicon made from the logo, the skip link, `<main id="main">`.
  - `SiteHeader.astro`: logo and wordmark, inline links, an always-visible Download button, and a native `<details>` Menu below 720px.
  - `SiteFooter.astro`, and `navigation.ts` (one list of links, shared by the header, menu, footer and 404).
  - `tokens.css`: light values plus dark under `prefers-color-scheme`, following `theme.ts` and `surfaces.css`.
  - `base.css`: page defaults, a 3px focus ring, reduced motion.
- **`src/pages`:** `index.astro` is a minimal hero using the proposal's draft hero copy; the homepage ticket replaces it. `404.astro` names the problem and links Home, Download, Documentation and Releases.
- **Logo:** `docs/assets/knightbook-logo.png` is the only source. sharp resizes it at build time, 554 kB to 3 kB at 32px (1× and 2×).
- **Formatting:** Prettier formats `.astro` through `prettier-plugin-astro`, and `.astro/` (generated types) is ignored.

**How it was checked.**
- `pnpm check` passes. Website: 11 tests, and `astro check` reports 0 errors and 0 warnings. Everything else is unchanged: core 275, MCP 47, desktop 649 (3 skipped), editor-preservation 21 (3 skipped), packaging 54 (1 skipped). Lint and format are clean.
- `layout.test.ts` builds the real site into a temporary folder and checks the HTML:
  - no `.js` or `.mjs` file and no `<script>`;
  - the skip link is the first element and points to `#main`, on both pages;
  - the logo (empty alt) and wordmark sit in the brand link;
  - each of the three links, with its label, is inside the inline nav and again inside the `<details>` menu;
  - Download sits in the header and outside the menu;
  - the footer has Download, Documentation and Releases on both pages;
  - the 404 has its title, heading and four way-back links.
- `tokens.test.ts` checks:
  - every named token exists;
  - every colour token has a dark value;
  - WCAG contrast is at least 4.5:1 for 13 text and surface pairs, in light and in dark.
- In the browser, against the production build (`preview:website`):
  - **1280px light:** links inline, menu hidden, no horizontal scroll, no scripts.
  - **375px dark:** inline links hidden, Menu shown, Download visible 12px from the top, no horizontal scroll. Clicking Menu opens it with no JavaScript, and its links are 42px tall.
  - **Keyboard:** Tab first focuses "Skip to content" with a 3px outline, and Enter moves focus to `<main>`.
  - **404:** the 404 page rendered.
  - Screenshots were taken of the 404 at 375px dark and the homepage at 1280px light.
- That pass found two things, both fixed:
  - Download touched the top edge at 375px.
  - The Menu summary had its native display overridden.
- Verifier: 3 covered, 2 weakly covered, 1 uncovered, 2 not code criteria. Its gaps were closed afterwards:
  - links are now checked inside the header and menu specifically;
  - all three menu links are checked;
  - the footer is checked on both pages;
  - the 404's links are checked;
  - a token and contrast test was added;
  - a misnamed test was renamed.

**Not verified.**
- **Narrow-screen visibility** (Download visible, inline links hidden below 720px) is only a manual browser check. No browser test runs in CI.
- **"CI runs its build":** the build happens in CI only because `pnpm check` runs `layout.test.ts`, which builds the site. There is no separate build step in `ci.yml`.
- **Footer:** it has no license or support slot yet. Those links join the shared list once they are chosen (a677c856, c125336d), so no link points at an undecided page.
- **Dead header links:** the links to `/docs/`, `/releases/` and `/download/` lead to the 404 page until their tickets add those pages.
- **Release:** this PR changes `pnpm-lock.yaml` and the root `package.json`, which count as the app (D-041), so merging it releases a patch.
- **Linting `.astro` files:** whether oxlint looks inside `.astro` frontmatter is unverified. `astro check` typechecks it.
